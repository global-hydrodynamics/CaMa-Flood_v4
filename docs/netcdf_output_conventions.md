# NetCDF output conventions in CaMa-Flood v5

New CaMa-Flood-generated NetCDF data use NetCDF-4 with lossless zlib/deflate level 3 and the shuffle filter where the writer supports those filters. Compression does not reduce numerical precision or alter dimensions, variable order, metadata, or scientific meaning. Existing files are not recompressed automatically. NetCDF files supplied as external inputs do not need to follow this output setting. A format exception is retained where an established compatibility contract requires it.

## Format exceptions and excluded writers

`map/tools/code/param_channel_calc_rivwth.F90` retains `NF90_64BIT_OFFSET` (NetCDF classic 64-bit-offset format), which does not support NetCDF-4 deflate filters. This established parameter-product format is left unchanged for compatibility. Test-fixture NetCDF writers are not production outputs and are not altered merely to match the defaults.

Historical v4 writers under `src/` and `map/src/`, plus the existing legacy `etc/` preprocessing workflows, are outside the active v5 scope and remain unchanged. External NetCDF datasets downloaded or supplied as inputs are not generated by CaMa-Flood and need not be compressed. Existing test fixtures intentionally retain their minimal formats.

## Reader compatibility

The v5 model uses NetCDF-Fortran for forcing, individual map rasters, output, and Restart data. Deflate and shuffle are transparent to those readers; the data contract remains the variable type, dimensions, order, and metadata defined by each workflow. Format-conversion checks confirm data preservation; model-reader compatibility should be checked when a writer or input path changes.
