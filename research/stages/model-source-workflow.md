The implementation and end-to-end comparisons are recorded in DT-0047 and VR-0091. `src_main/cmf_ctrl_maps_mod.F90` now routes individual raster reads through shared helpers, validates NetCDF type and dimensions, preserves Binary direct-access records/byte handling, and supports mixed input formats without new namelist keys. `map/tools/code/convert_map_binary_to_netcdf.py` uses the variable registry and `params.txt`; the Mekong core rasters were converted into temporary validation data only.

On macOS/Homebrew GNU Fortran, the Binary-only and NetCDF-enabled builds succeeded. The 40-day Mekong run completed for all-Binary, rivhgt-only NetCDF, nextxy-only NetCDF, and all-nine-core-map-input NetCDF configurations. For each NetCDF-enabled scenario the five selected model output files matched the same-executable all-Binary baseline byte-for-byte. The rebuilt Binary-only executable also matched the prior Binary baseline. Unsupported-extension, missing-variable, dimension-mismatch, and Binary-only `.nc` / legacy-CDF-mode failures were checked. This verifies operational I/O compatibility for the sample, not scientific validity or all optional map pathways. At the initial implementation report, runtime validation of optional groundwater, mean-sea-level, MPI, slope/mask, and legacy consolidated NetCDF inputs remained pending; the subsequent scope clarification below specifically rejects slope/mask options in individual mode and reruns affected cases.


### Individual Map-input scope clarification

After the initial implementation, the maintainer clarified that individual `.bin`/`.nc` dispatch under `LMAPCDF=.FALSE.` must cover only variables read through the old Binary path. The prior individual readers for ECMWF-specific `elevslope` and `mask_slope` were removed. `LSLOPEMOUTH` and `LSLPMIX` now fail early and explicitly in individual-file mode; their legacy consolidated-NetCDF routines remain in their old path. Source inspection found that the historic `elevslope` read follows a close of its NetCDF handle and `SET_SLOPEMIX` uses a handle it does not open. Those pre-existing issues are documented, not repaired here.

In a later bounded task, the maintainer authorized fixing those two legacy NetCDF handle lifecycle bugs without extending individual-file support or changing scientific behavior. `elevslope` is now read while `CRIVPARNC` is open, and `SET_SLOPEMIX` opens and closes `CRIVPARNC` around `mask_slope`. Both build variants and five 40-day Mekong Binary/individual-NetCDF regression cases passed after the fix; five selected outputs remained byte-identical. The legacy slope-option runtime still lacks a suitable consolidated NetCDF fixture. See ADR-0006 and VR-0093.

The corrected source rebuilt in both Binary-only and NetCDF-enabled configurations. The 40-day Mekong Binary-only baseline, NetCDF-executable Binary case, rivhgt-only and nextxy-only mixed cases, and all-nine-core-input NetCDF case completed. The five selected model outputs were byte-identical across these runs, and direct typed comparisons confirmed exact values for all nine converted map products, including both `nextxy` records and ten `fldhgt` layers. Both individual-mode slope guards were exercised and returned status 9 before topography reads. No legacy consolidated NetCDF fixture was found, so that route remains unverified at runtime. The clarification and validation are recorded in ADR-0005 and VR-0092; they supersede the broader slope-input scope in the initial implementation summary while preserving its chronology.


## Restart state-I/O refactor

The maintainer approved a structural refactor of `cmf_ctrl_restart_mod.F90` to make model-state selection and file representation independently readable. The principal `CMF_RESTART_INIT` and `CMF_RESTART_WRITE` procedures now show Normal/Storage-only behavior and option-gated state lists, while private generic `RESTART_UTIL_READ` and `RESTART_UTIL_WRITE` procedures route JPRM/JPRD arrays through the existing Binary or NetCDF implementations. The overloads compile both when `JPRB` is distinct from `JPRD` and when they are the same kind.

The reason for the split is maintainability: developers can review which state belongs to a Restart without tracing file encodings and conversion helpers. The implementation retained existing Binary records, NetCDF variables and precision, optional-state ordering, bifurcation-path behavior, and timing. Default Binary, NetCDF, and double-kind builds passed. One-day Mekong Normal Restart comparisons against the prior source were byte-identical for the tested Restart and selected model-output files in both Binary and NetCDF formats. NetCDF Storage-only write/read completed. Optional schemes, MPI, and coupled runs were not exercised. Details and limitations are in [VR-0117](../records/validation_runs/VR-0117.md).


## Interactive workstation setup

The repository-root `s01-setup_fortran.sh` checks compiler and library readiness with small compile/link tests and offers to generate a machine-specific root `Mkinclude`. It does not install packages or modify `adm/Mkinclude`; the user activates the reviewed configuration manually. `s02-python_setup.sh` diagnoses Python and offers to create or update the local `.venv/` using the unchanged `requirements.txt`. Both scripts ask before filesystem changes and only diagnose when no interactive terminal is attached. Component availability is reported separately from simulation execution. The scripts were tested on macOS/Apple Silicon; unsupported/missing components and user-declined changes were exercised with controlled mocks. See [DT-0074](../development_tasks.csv) and [VR-0119](../records/validation_runs/VR-0119.md).

## Tutorial 02 experiment-specification investigation

The maintainer authorized source/data-contract investigation and finalization of the English experiment specification, while keeping scripts, simulations, figures, README authoring, and package changes out of scope. The specification now distinguishes the three intended physical configurations from shared compatibility settings. Source inspection confirmed that Kinematic Wave with bifurcation enabled stops configuration, while adaptive time stepping is discouraged for that scheme; the proposed shared settings therefore use fixed `DT=3600`, disable adaptive stepping, and recommend disabling bifurcation across all three experiments. The shared bifurcation choice remains for maintainer confirmation because it differs from the bifurcation-on `mek01` sample.

The source also shows that a no-Restart initialization zeros prognostic arrays and then initializes channel storage against the downstream boundary elevation, so the starting condition should not be described as uniformly zero storage. NetCDF output records daily means at the end of each averaging interval. The GRDC allocation table supplies candidate Mekong locations and map cells, but the final teaching-site selection remains open. Only annual runoff NetCDF for 2000–2001 was Git-tracked at that review; local untracked 2002–2003 files were not treated as reproducible inputs. ## Tutorial 02 implementation and execution

In the next approved stage, the maintainer selected five sampling locations: Vientiane, Ubon Ratchathani (Mun), Stung Treng, Prek Kdam (Tonle Sap), and Can Tho (Hau/Bassac delta). Four sites use GRDC allocations; Can Tho uses the MRC water-quality station H039803 as geographic context. Their model cells and downstream connectivity were checked against the Mekong 15-minute map. This selection defines simulation sampling only; no observed discharge series was used.

Four independent experiment scripts and three visualization programs plus a sequential wrapper were implemented in `tutorial/tutorial02-mekong_netcdf_4exp/`. The NetCDF model built with GNU Fortran 14.2.0 on macOS Apple Silicon. All 16 annual runs for 2000–2003 completed, with annual NetCDF runoff, map and output input, and NetCDF Restart handoffs. Each experiment produced 1,461 continuous daily records. The spin-up overlay, five-location hydrographs, annual maximum maps for 2001–2003, and station-location map were generated and visually reviewed. At Prek Kdam, negative discharge occurs in both Local Inertial cases and not in the two Kinematic Wave cases. At Can Tho, Default and No Bifurcation differ on every 2001–2003 daily record. These are model-behavior observations, not observational validation or proof that the coarse cells represent local river processes adequately.

The experiment specification records selected locations, actual output checks, runtime evidence, and open scientific interpretation questions. The beginner-facing README and package assembly remain deferred. See DT-0078, DR-0062, KG-0034, and VR-0123.
