# KG-0027: Legacy consolidated and optional map-input behavior

- **Gap ID:** KG-0027
- **Linked event ID(s):** EV-0287; EV-0288; EV-0290; EV-0291; EV-0292; EV-0293
- **Category:** compatibility / map I/O coverage
- **Evidence basis:** source-code and dataset inspection
- **Status:** partially_formalized

## What was unknown or assumed?

The supported scope is now clarified: which maps are eligible for new individual-file NetCDF input, and whether the two identified legacy consolidated slope-reader handle defects should be corrected. The maintainer authorized and the implementation corrected those defects without changing the legacy input contract. Runtime compatibility for `LMAPCDF=.TRUE.` remains unverified because no consolidated fixture is available.

## How was it discovered?

The first individual-file implementation extended two ECMWF-specific slope inputs beyond the legacy Binary reader set. The maintainer clarified that this was outside scope. The repository Mekong sample and the inspected local v4.30 map package contain independent Binary rasters, not the legacy consolidated NetCDF containers, so the consolidated runtime path remains untested.

## Verified facts

- `LMAPCDF=.TRUE.` selects the legacy consolidated NetCDF map readers and their existing containers (`CRIVCLINC`, `CRIVPARNC`, `CMEANSLNC`, and `CMPIREGNC`).
- Individual `.bin` / `.nc` dispatch under `LMAPCDF=.FALSE.` is limited to maps previously read by the Binary path, including core topology/parameter rasters, optional `CGDWDLY` and `CMEANSL`, and MPI `CMPIREG`.
- `elevslope` (`LSLOPEMOUTH`) and `mask_slope` (`LSLPMIX`) are legacy consolidated-NetCDF-only inputs. Individual-file mode now reports an explicit error before these options can use uninitialized arrays.
- The old consolidated `elevslope` read used `NCID` after closing the `CRIVCLINC` file, before opening `CRIVPARNC`. `SET_SLOPEMIX` used its local `NCID` without opening a file. Both were source-observed handle-lifecycle defects, not scientific-method issues. Under a separate maintainer instruction, `READ_TOPO_CDF` now reads `elevslope` while `CRIVPARNC` is open, and `SET_SLOPEMIX` explicitly opens `CRIVPARNC` for `mask_slope` and closes it after reading. No equations, variable meanings, namelist settings, or individual-file behaviors changed.
- Binary-only and NetCDF-enabled builds, the all-Binary baseline, mixed individual-file cases, and the all-core-individual-NetCDF case passed after the scope correction. Five selected model output files matched byte-for-byte. Both individual-mode slope guards returned nonzero status with a direct diagnostic.
- No suitable legacy consolidated map fixture was found in the repository sample or inspected local package, so `LMAPCDF=.TRUE.` runtime behavior was not reverified.

## How was the knowledge formalized?

`src_main/README.md`, `docs/model_source_workflow_plan.md`, and ADR-0005 define the two-path contract. ADR-0006 records the approved legacy handle repair. VR-0091 records the initial individual-file validation; VR-0092 records validation after the scope correction; VR-0093 records builds and Mekong regression checks after the handle repair.

## Resolution trace

- **Resolution method:** maintainer decision, source inspection, build checks, and individual-input runtime regression.
- **Evidence or maintainer explanation:** the maintainer retained legacy consolidated NetCDF support, prohibited new individual-file support for these special options, and separately authorized fixing the two file-ID errors. No legacy consolidated fixture is available for runtime comparison.
- **Final interpretation and rationale:** the individual-file contract remains deliberately narrow and has no new slope-file or namelist contract. The two slope options are rejected in individual mode to prevent use of absent/uninitialized values. In legacy mode, each special variable is now read from `CRIVPARNC` while that file handle is open. The affected mechanisms are corrected, but direct runtime proof for the special consolidated inputs is still needed when a suitable fixture is available.
- **Formalization location(s):** `src_main/cmf_ctrl_maps_mod.F90`; `src_main/README.md`; `docs/model_source_workflow_plan.md`; ADR-0005 and ADR-0006; VR-0092 and VR-0093.
- **Human review:** maintainer-confirmed scope

## Verification and limits

The Binary-only and NetCDF-enabled builds passed after the handle fixes. Five 40-day Mekong cases (Binary executable and NetCDF executable with Binary, mixed, and all-core individual NetCDF maps) completed; five selected outputs were byte-identical across cases. Both individual-mode slope errors remained explicit. These results do not validate `LMAPCDF=.TRUE.`, MPI runtime, groundwater delay, mean sea level, or the consolidated slope-option runtime because no suitable fixture is available. Source inspection confirms the two handle lifecycle defects are corrected.

## Why the gap matters

Legacy and optional inputs are part of the established model interface. A suitable fixture and explicit run configuration are needed to distinguish compatibility defects from missing test data before making broader support claims.
