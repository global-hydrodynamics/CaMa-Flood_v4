# KG-0015: Intended MLIT level-gauge input table

- Gap ID: KG-0015
- Linked event IDs: EV-0179, EV-0193, EV-0196, EV-0197
- Category: input schema / provenance
- Evidence basis: wrapper/package inspection and maintainer-approved v5 interface
- Status: resolved_for_v5

## What remains unknown?

Which MLIT file should the new v5 level-gauge wrapper consume, given the historical v4 script points to a missing `MLIT_allocated.csv` while the canonical processed file is `MLIT_LevelGauge_allocated.csv`?

## How was it discovered?

t03-alloc_level_gauge.sh names ../../data/MLIT_allocated.csv, but that file is absent from both the inspected repository data directory and the v4.30 package. The package contains MLIT_LevelGauge_allocated.csv, whose first four column names and record layout appear compatible with the reader's positional first-four-field contract. At Phase A, the filename and omitted processing history prevented treating a v5 substitution as confirmed. The Phase B task later explicitly approved the canonical `map/data/MLIT_LevelGauge_allocated.csv` for v5 and required the v4 wrapper remain unchanged.

## Verified facts

- The level-gauge program skips one header row, then reads ID, latitude, longitude, and upstream area.
- The package's MLIT_LevelGauge_allocated.csv begins with ID,lat_alloc,lon_alloc,area_alloc and has 7,539 data rows.
- `map/data/MLIT_allocated.csv` is not present; the historical v4 shell reference is not runnable with the inspected package contents.
- The v5 wrapper uses `map/data/MLIT_LevelGauge_allocated.csv` as approved in Phase B.
- The package also has MLIT_FlowGauge_alloc_final.csv, but no corresponding workflow among the three inspected scripts consumes it.

## How was the knowledge formalized?

The historical v4 mismatch remains documented; the v5 wrapper uses the maintainer-approved canonical input path.

## Resolution trace

- Resolution method: maintainer-approved Phase B interface instruction.
- Evidence or maintainer explanation: `EV-0193`; the canonical tracked path and its header; `map/tools/script_params/t03-alloc_level_gauge.sh`.
- Final interpretation and rationale: v5 uses `MLIT_LevelGauge_allocated.csv`; this approved interface choice does not claim identity with any absent `MLIT_allocated.csv`. The legacy v4 wrapper is preserved unchanged.
- Formalization location(s): `docs/map_allocation_migration_plan.md`; `map/tools/script_params/README.md`; v5 wrapper.
- Human review: approved in Phase B task instructions.

## Verification and limits

The observed file path, header, and row count are reproducible. The historical v4 filename origin remains undocumented, but the v5 input choice is resolved and does not require reconstructing that history.

## Why the gap matters

The approved v5 path makes the study population reproducible. The historical v4 path remains a compatibility fact rather than a v5 implementation blocker.
