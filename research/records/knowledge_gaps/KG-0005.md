# KG-0005: Historical origin and external consumers of basin-connectivity maps

- Gap ID: `KG-0005`
- Linked event ID(s): `EV-0105`
- Category: bifurcation workflow / MPI downstream use
- Evidence basis: Maintainer-approved clarification and current in-repository MPI source/workflow
- Status: partially formalized

## What remains unknown?

The maintainer suspects that the ordinary basin-connectivity implementation may have originated during earlier MPI-related development and that historical MPI language remained in comments. This is explicitly a hypothesis, not verified project history. The current in-repository MPI path is documented and does not directly consume ordinary `bifbsn.bin`; whether external or historical workflows use it indirectly is outside the current evidence.

## Verified current workflow

- Standard s02 reads `basin.bin` and `bifprm.txt`; `param_set_bif_basin` writes ordinary `bifbsn.bin` and its diagnostics.
- The current MPI preparation separately reads `basin.bin` and `bifprm.txt`; `set_bif_basin_mpi` writes `bifbsn_mpi.bin`.
- `set_mpi_region` reads `bifbsn_mpi.bin` and generates processor-region products.
- The current verified MPI path does not read ordinary `bifbsn.bin` directly.

The workflow is summarized in `docs/map_params_migration_plan.md`, with supporting source in `map/src/src_param/set_bif_basin_mpi.F90`, `set_mpi_region.F90`, and `s03-mpi_map_setup.sh`.

## Why the gap remains

The current file dependency is clear enough to document the standard and MPI products separately and to proceed with the current migration. Historical origin and use outside the inspected repository cannot be established from these sources. No further investigation is needed unless a later task documents historical provenance or an external integration.
