# KG-0014: High-resolution area selection and tiled-map support

- Gap ID: KG-0014
- Linked event IDs: EV-0179, EV-0193, EV-0196, EV-0197
- Category: architecture / map data contract
- Evidence basis: legacy source inspection and maintainer-approved Phase B scope
- Status: resolved_for_phase

## What remains unknown?

Phase A left open whether v5 had to support multiple high-resolution areas. Phase B approval set the scope: require explicit `HIRES_TAG`, support one area, and reject multi-area/tiled layouts.

## How was it discovered?

The three programs probe 1min/location.txt, accept it only when the declared area count is one, and otherwise try 15sec/location.txt. They then parse one area row and load one set of <tag>.<layer>.bin files. The readers do not loop over tiles or resolve path traversal across area boundaries. The Mekong sample is one 1min area, so it does not expose this limitation.

## Verified facts

- allocate_flow_gauge.F90, allocate_dam.F90, and allocate_level_gauge.F90 use the same 1min-then-15sec selection pattern.
- Each reader loads one uparea, catmxy, and downxy layer set; the level-gauge tool also loads one high-resolution elevation layer.
- The current Mekong 1min/location.txt declares one area with 1200 x 1800 cells.
- The v5 wrappers conventionally distinguish high-resolution map selection with HIRES_TAG, whereas these legacy programs hard-code their fallback selection.

## How was the knowledge formalized?

The Phase B task explicitly approved the single-area boundary and explicit `HIRES_TAG`, allowing implementation without inventing tile traversal.

## Resolution trace

- Resolution method: maintainer-approved task scope plus implementation validation.
- Evidence or maintainer explanation: Phase B task specification (`EV-0193`); legacy source inspection; `map/tools/tests/test_allocation_regression.py`.
- Final interpretation and rationale: the first migration supports one selected area to preserve the actual legacy reader shape. Tiled support requires a separate design and cross-tile path validation.
- Formalization location(s): `docs/map_allocation_migration_plan.md`; `map/tools/script_params/README.md`; `map/tools/code/mod_allocation_map_io.F90`.
- Human review: approved in Phase B task instructions.

## Verification and limits

The regression test confirms that multi-area layouts are rejected by v5. This does not establish the layout of every distributed map or implement tiled traversal.

## Why the gap matters

Tiled map selection and cross-tile network tracing can change matching results and interfaces, and may require additional data structures and tests. The choice should precede shared-reader architecture.
