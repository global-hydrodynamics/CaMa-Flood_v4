# KG-0003: Module-level NetCDF map producer contract is incomplete

- Linked event: `EV-0006`
- Category: interface / file format
- Evidence basis: Fortran reader source and maintainer-confirmed workflow provenance recorded in the map specification
- Status: partially verified; output contract open

## Verified facts

The model's NetCDF map readers request module-level files through `CRIVCLINC` and `CRIVPARNC`. The package inspected for the map inventory did not contain these outputs, and their generation was performed at ECMWF. The maintainer stated that the generation code should be added. The repository's first category-11 converter writes a `CRIVCLINC`-compatible core map but does not generate the channel-parameter `CRIVPARNC` file or cover optional schemes.

## Formalization and remaining unknowns

Current reader observations and limitations are recorded in [`docs/map_data_inventory.md`](../../../docs/map_data_inventory.md) and [`map/map_metadata_spec.md`](../../../map/map_metadata_spec.md). The full required variable sets, precise dimensions/order, attributes, missing-value behavior, and channel/optional-scheme outputs still need producer-contract verification before claiming compatibility.

## Why it matters

A future producer could appear to create NetCDF maps while omitting fields required by the model or coupled schemes. The existing core converter and synthetic reader-contract tests are useful independently; the complete ECMWF-equivalent output contract remains a separate implementation task.
