## What is unknown?

The tracked NetCDF samples have 31 daily timestamps. An initial workstation state had 31 ignored local binary files with two grids each and a CTL declaring 62 records at 1-day spacing. The maintainer suspected this was left from changing settings during testing, then reran the current 24-hour wrapper. The regenerated files have one grid per date and the CTL/report now declare 31 daily records.

## Verified evidence

- The tracked raw source and converted NetCDF each have 31 January 2000 timestamps on a 321×221 grid.
- The prior local state had 31 binary files of 567,528 bytes each (two 321×221 float32 grids), while the CTL said 62 records at `1dy`.
- After the maintainer's rerun, the current local files are 283,764 bytes each (one 321×221 float32 grid), with a CTL of 31 records at `1dy`.
- Current `convert_CMF_bin.py` sets the CTL time-record count from the number of output timestamps; with the tracked 31-time source and the current wrapper's 24-hour output interval, that code path would declare 31 records.
- Binary records are ignored by Git and are not present in a clean clone; their local size observation must not be treated as a repository-distributed sample.

## Remaining uncertainty and impact

The maintainer reports that rerunning the current 24-hour wrapper produced 31 files of 283,764 bytes each (one 321×221 float32 grid) and a 31-record, 1-day CTL. This agrees with the tracked 31-time NetCDF and converter's output-count behavior. The exact origin of the earlier two-grid files remains unverified, and agreement of layout does not scientifically validate values.
