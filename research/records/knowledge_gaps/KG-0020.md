## What is unknown?

Which input timestep and wrapper settings produced the tracked `runoff.ctl`, report, and ignored local binary records under `inp/download_ERA5/runoff_japan_bin/`? Do they represent a previously configured subdaily output, stale output, or files modified independently?

## Verified evidence

- The tracked raw source and converted NetCDF each have 31 January 2000 timestamps on a 321×221 grid.
- The tracked binary CTL declares 62 time records at `1dy`; the tracked text report also states 62 records and a 24-hour interval.
- The 31 local ignored binary files are each 567,528 bytes, exactly two 321×221 float32 arrays.
- Current `convert_CMF_bin.py` sets the CTL time-record count from the number of output timestamps; with the tracked 31-time source and the current wrapper's 24-hour output interval, that code path would declare 31 records.
- Binary records are ignored by Git and are not present in a clean clone; their local size observation must not be treated as a repository-distributed sample.

## Unresolved interpretation and impact

The artifact mismatch cannot identify which historical setting produced the files. Treating the CTL as describing the two records per file would also require interpreting its 1-day interval and the report's 24-hour `DROFUNIT`; no evidence establishes that this is correct. The files should not be described as a verified binary sample or used as a validation baseline.
