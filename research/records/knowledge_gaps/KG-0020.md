# KG-0020: Provenance and record layout of the Japan binary sample

- Gap ID: `KG-0020`
- Linked event ID(s): `EV-0231`

- Evidence basis: maintainer clarification, current source inspection, and read-only comparison of tracked and ignored files; binary values and historical execution settings remain unavailable
- Status: partially formalized; does not block synthetic testing or documentation

## What is unknown?

The tracked NetCDF samples have 31 timestamps, while each of the 31 ignored local binary files has room for two grids. The maintainer identified the tracked CTL's 62 records at 1-day spacing as a CTL error and directed correction for the observed two-record-per-day layout. The current tracked wrapper is still configured for 24-hour records, so it does not reproduce that layout.

## Verified evidence

- The tracked raw source and converted NetCDF each have 31 January 2000 timestamps on a 321×221 grid.
- Before correction, the tracked binary CTL declared 62 time records at `1dy`; the tracked text report also said 62 records and a 24-hour interval. Both tracked text files are now corrected to describe 62 records at `12hr`.
- The 31 local ignored binary files are each 567,528 bytes, exactly two 321×221 float32 arrays.
- Current `convert_CMF_bin.py` sets the CTL time-record count from the number of output timestamps; with the tracked 31-time source and the current wrapper's 24-hour output interval, that code path would declare 31 records.
- Binary records are ignored by Git and are not present in a clean clone; their local size observation must not be treated as a repository-distributed sample.

## Remaining uncertainty and impact

The local file sizes establish two records per daily file but do not verify the physical meaning or values of those records. The current tracked NetCDF and current conversion wrapper use 24-hour records and would produce 31 records, not 62. The 12-hour CTL/report is therefore a correction of the observed local layout, not a reproducible conversion result or scientific validation. The files should not be used as a scientific validation baseline.
