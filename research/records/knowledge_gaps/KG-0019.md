# KG-0019: ERA5-Land accumulated runoff time labels and daily increments

- Gap ID: `KG-0019`
- Linked event ID(s): `EV-0224`
- Category: scientific time semantics / input-output contract
- Evidence basis: source-code inspection and official product documentation; intended interpretation not maintainer-confirmed
- Status: open; important before changing or claiming ERA5-Land conversion semantics

## What was unknown or assumed?

Which simulation date should receive an ERA5-Land runoff accumulation with valid timestamp 00:00, and how should the first value in a daily conversion group be interpreted? This concerns both the existing v4 workflow's temporal alignment and any future v5 converter contract.

## How was it discovered?

During the Phase A inventory, inspection found that `download_era5land.py` requests `00:00` as the first time of every selected day (`make_times`, `make_request`), while both converters group records by UTC calendar date and retain that group's first accumulated value. The [ECMWF ERA5-Land documentation](https://confluence.ecmwf.int/pages/viewpage.action?pageId=143034781) states that a CDS valid-time 00:00 accumulation covers the preceding 24 hours. This mismatch could shift daily forcing labels or affect start/end coverage. It must be resolved before modifying conversion behavior or claiming date-aligned forcing.

## Verified facts

- `download_era5land.py` requests the selected runoff variable at times generated from `00:00` in steps of `time_step` hours.
- `convert_CMF_nc.py` groups by UTC calendar date, differences within each group, and defaults the first value to `keep`; it replaces negative differences with the current accumulated value and clips negatives by default.
- `convert_CMF_bin.py` uses the same calendar-day grouping and negative-difference fallback, and keeps the first daily value without a CLI alternative.
- The tracked Japan raw sample has timestamps at daily 00:00 and 31 records for January 2000; its converted sample retains 31 daily-labelled records. These observations establish current behavior, not whether its labels match the intended physical accumulation periods.
- ECMWF's product documentation describes ERA5-Land accumulations from the daily forecast start and states that valid time 00:00 represents the previous day.

## Unresolved interpretation

It is not established whether the intended CaMa-Flood date label denotes the ERA5-Land valid timestamp or the calendar day covered by the accumulated amount. Nor is it established whether daily input should query 00:00 or another time, how subdaily first values should be attributed across daily forecast cycles, or what first/last timestamp coverage is required for an inclusive simulation period.

## Why the gap matters

A one-day shift, dropped boundary accumulation, or incorrect daily total changes the forcing applied during a model run. Temporal interpretation therefore affects reproducibility and scientific output, not just file naming. Independent schema, dependency, and test planning can continue while this question awaits maintainer review.
