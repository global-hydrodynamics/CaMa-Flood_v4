# KG-0018: Legacy subbasin tool aborts at the 30,000 km2 sample threshold

- Gap ID: `KG-0018`
- Linked event IDs: `EV-0212`–`EV-0214`
- Category: legacy implementation / runtime compatibility
- Evidence basis: observed runtime failure in a legacy/v5 comparison attempt
- Status: open; non-blocking for the v5 sample update

## What was unknown or assumed?

It was not known whether the preserved v4 `map/src/src_param/get_subbasin.F90` could generate a 30,000 km2 comparison raster on the current compiler. This matters only if legacy output comparison or v4 use at this threshold is required; the approved sample update targets the v5 tools and does not authorize modifying legacy code.

## How was it discovered?

During regression, the legacy executable was run with threshold `30000` on the Mekong sample using GNU Fortran 14.2.0. It aborted after printing its basin-color setup with a runtime assertion in the Fortran runtime (`newunit_free`, `unit.c`); the program returned `-6`. The failure is recorded contemporaneously in EV-0212. The v4 source was left unchanged.

## Verified facts

- The failure occurred in this local macOS/GNU Fortran 14.2.0 environment during the attempted 30,000 km2 legacy comparison.
- The legacy/v5 comparison at 50,000 km2 passes in the final test suite.
- The v5 30,000 km2 sample workflow passes and writes the labeled sample products.
- The runtime assertion does not, by itself, establish the source-level cause or prove failure on other compilers/platforms.

## How was the knowledge formalized?

This record and the Phase C follow-up in `docs/map_params_migration_plan.md` identify the observed failure and its validation boundary.

## Resolution trace

- Resolution method: unresolved; source-level cause not diagnosed
- Evidence or maintainer explanation: failing legacy invocation in EV-0212; final regression command and environment in VR-0069
- Final interpretation and rationale: Keep the legacy source unchanged. Use legacy comparison at its previously supported 50,000 km2 example and test the 30,000 km2 sample behavior in v5. A separate legacy repair requires a new scope decision.
- Formalization location(s): `research/records/knowledge_gaps/KG-0018.md`; `research/records/discussions/DR-0042.md`; `map/tools/tests/test_analysis_migration.py`
- Human review: pending

## Verification and limits

A complete v5 map-tools test run passes after the comparison is scoped as above. The legacy 30,000 km2 abort has not been isolated or reproduced across additional compilers, and its mechanism remains unknown.

## Why the gap matters

If users need the old v4 program to operate at this lower threshold, it may fail at runtime on at least one compiler configuration. No legacy fix is made without an explicit maintainer task because `map/src/` is retained as historical code.
