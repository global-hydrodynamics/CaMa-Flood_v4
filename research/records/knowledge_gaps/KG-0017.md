# KG-0017: Subbasin terminal-link indexing and safe exploratory outputs

- Gap ID: `KG-0017`
- Linked event IDs: `EV-0208`–`EV-0210`
- Category: workflow / numerical implementation safety / interface
- Evidence basis: source-code and bounds-check test; maintainer-confirmed boundary
- Status: closed

## What was unknown or assumed?

The legacy `get_subbasin` compares each cell's upstream area with that of its downstream cell when a candidate boundary is considered. It was unclear whether every negative downstream code could safely be used as an array index. It was also unclear how an exploratory threshold could write separate files without overwriting the standard `subbsn.bin` and `subcol.bin` outputs.

## How was it discovered?

Compiling and running the Mekong workflow with bounds checking caused an out-of-range index on a terminal link. Inspection also found diagnostic arrays indexed by `basin=-999` for below-threshold outlets. Both issues arose in `map/src/src_param/get_subbasin.F90`; the latter arrays are not used in subsequent output calculation. This matters because valid sample maps include terminal links and the analysis workflow should be safe under runtime bounds checks.

## Verified facts

- The legacy area-boundary rule compares upstream areas in km2 and cuts when the downstream area exceeds the current area by more than the selected threshold, after the current area exceeds the threshold.
- Negative terminal codes are not valid one-based grid indices; comparison must be restricted to valid downstream coordinates.
- The secondary `basin_size`, `basin_order`, and `basin_new` arrays are populated for later diagnostic/ordering logic that is not used by this program's output path; only positive assigned basin IDs are valid indices.
- The maintainer approved a v5-only bounds guard and an optional pair of CLI output paths. Default arguments and numerical cut rule remain unchanged.

## How was the knowledge formalized?

The v5 source checks downstream coordinate bounds before dereferencing and only indexes the unused diagnostics for positive basin IDs. The optional CLI is `analysis_get_subbasin THRESHOLD_KM2 [SUBBSN_OUTPUT SUBCOL_OUTPUT]`; the paths must be supplied as a pair. Tests compare legacy and v5 default products byte-for-byte on the Mekong sample and exercise v5 with `-fcheck=bounds` and custom paths.

## Resolution trace

- Resolution method: mixed
- Evidence or maintainer explanation: bounds-check execution and source inspection; maintainer approval of the v5-only correction and paired output paths.
- Final interpretation and rationale: avoid invalid array access on terminal and unassigned cells, while retaining the legacy segmentation decision rule and default filenames. Custom paths allow exploratory analysis to preserve standard outputs.
- Formalization locations: `map/tools/code/analysis_get_subbasin.F90`; `map/tools/tests/test_analysis_migration.py`; `map/tools/script_analysis/a03-subbasin.sh`; `docs/map_params_migration_plan.md`.
- Human review: pending

## Verification and limits

The Mekong legacy/v5 `subbsn.bin` and `subcol.bin` outputs match byte-for-byte at the example threshold; v5 bounds-check execution succeeds and custom files do not replace standard names. This does not validate the scientific choice of threshold or prove correctness for all map topologies. The legacy source remains unchanged.

## Why the gap matters

Invalid indexing can terminate analysis or access undefined memory on ordinary terminal outlets. Unbounded default filenames would also make exploratory parameter sweeps prone to replacing standard products.
