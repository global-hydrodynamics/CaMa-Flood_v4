# KG-0008: Runtime role and intended use of `prmwat.bin`

- Gap ID: `KG-0008`
- Linked event IDs: `EV-0170`, `EV-0171`, `EV-0172`
- Category: workflow / product semantics
- Evidence basis: maintainer-confirmed purpose plus source-reader inspection
- Status: partially_formalized

## What was unknown or assumed?

The existing registry described `prmwat.bin` as an optional model/workflow input, which left unclear whether the current simulation reads it and what the area represents.

## How was it discovered?

The migration request distinguished post-processing use from runtime simulation and specified that the product is catchment-aggregated area, not a pixel mask. This matters for registry use/runtime fields and for readers deciding whether the product is a required map input.

## Verified facts

- Legacy `calc_prmwat.F90` writes one float32 record and does not itself identify a current simulation reader.
- The maintainer confirmed the area is intended to exclude existing permanent water when estimating newly flooded area during post-processing and is not currently used by the simulation.
- The migrated map core and readers were not broadly audited for all external consumers; the statement is bounded to the current repository's simulation core as specified by the maintainer.

## How was the knowledge formalized?

The `prmwat.bin` row in `map/map_variables.csv` now describes its m2 units, one-record layout, stored `-9999` sentinel, valid-zero meaning, post-processing usage, and lack of a current core reader. The map metadata specification and parameter workflow README describe its catchment aggregation and purpose.

## Resolution trace

- Resolution method: mixed (source review and maintainer knowledge)
- Evidence or maintainer explanation: DR-0032 and HI-0004
- Final interpretation and rationale: optional post-processing reference area; not a current simulation-core input.
- Formalization locations: `map/map_variables.csv`; `map/map_metadata_spec.md`; `map/tools/script_params/README.md`
- Human review: pending

## Verification and limits

The migrated tool produced the specified data contract and matched legacy output on Mekong. This does not claim that downstream post-processing consumers outside this repository were exhaustively identified.

## Why the gap matters

Mislabeling this product as a simulation input could prompt users to treat it as a required model parameter or mistake it for a water mask.
