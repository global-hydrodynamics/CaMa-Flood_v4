# KG-0010: Whether missing `flddif` values should contribute to permanent-water area

- Gap ID: `KG-0010`
- Linked event IDs: `EV-0170`, `EV-0173`, `EV-0174`
- Category: missing-value semantics / scientific selection rule
- Evidence basis: source-code and sample analysis; intended behavior unresolved
- Status: open

## What remains unknown?

The legacy condition `flddif <= 5` accepts the stored value `-9999`. The task identified this as a possible unintended consequence of the missing-value convention but did not confirm whether such pixels should contribute scientifically. A new exclusion would change outputs for inputs containing a selected water-class pixel with `flddif=-9999`.

## How was it discovered?

Code inspection found that the threshold comparison has no explicit missing-value check. Mekong sample analysis found no selected candidate with `flddif=-9999`, so the ambiguity does not affect the reference regression. The synthetic regression includes the case to ensure that migration preserves legacy output.

## Verified facts

- The source comparison accepts `-9999` because it is numerically less than or equal to 5.
- The v5 implementation preserves this and prints a warning count rather than silently adding a filter.
- No selected missing-`flddif` combination was observed in the inspected Mekong reference data.
- Whether the missing value should be excluded in a future scientific behavior change is not confirmed.

## How was the knowledge formalized?

The code warning, workflow documentation, ADR-0004, and the test `test_legacy_classification_flddif_boundary_missing_value_and_cap` document the preserved behavior. This record marks the interpretation question as unresolved rather than treating legacy behavior as scientific intent.

## Resolution trace

- Resolution method: unresolved for scientific intent; source/test analysis established current behavior
- Evidence or maintainer explanation: legacy source and Mekong sample inspection; no scientific instruction to alter the rule
- Final interpretation and rationale: preserve exact legacy comparison in this migration; require separate maintainer approval for any filter that changes valid historical output.
- Formalization locations: v5 Fortran source, tests, parameter workflow README, ADR-0004
- Human review: pending

## Verification and limits

The sample has no affected selected pixels. The synthetic case confirms faithful migration of the legacy behavior, not that counting missing elevation differences is scientifically appropriate.

## Why the gap matters

A missing-value inclusion could inflate permanent-water area when such combinations occur in other maps; silently filtering it could also change historical results.
