# KG-0026: Package inclusion of annual Mekong NetCDF runoff sample

- Gap ID: `KG-0026`
- Linked event: `EV-0283`
- Category: data distribution / package workflow
- Evidence basis: repository inspection and task-scoped distribution policy
- Status: open

## Question

Should `inp/test-mek_1deg_nc/runoff2000.nc` and `runoff2001.nc` be included in a future downloadable CaMa-Flood v5 package, in addition to the GitHub repository?

## Discovery and evidence

The v5 sample was generated from the repository-tracked, redistribution-approved `inp/test-mek_1deg/` sample. Both NetCDF files are compact (888,596 and 886,172 bytes; about 1.7 MiB total) and exact float32 round-trip checks passed for all 731 daily fields. The existing `doc/make_package.sh` belongs to the legacy v4 packaging workflow; no v5 package assembly workflow is established for adding the new v5 sample.

## Why the decision matters

Package inclusion would make the yearly NetCDF forcing sample available without requiring users to run the conversion tool, but updating or extending the legacy v4 package script could mix v4 and v5 distribution contracts. The sample is already intended for repository tracking; this question concerns future downloadable package contents only. Conversion, testing, and repository documentation can proceed without a package decision.

## Current handling

The registry and dataset README describe the sample as a compact repository sample and state that package inclusion awaits a v5 packaging workflow. No legacy packaging script was changed.
