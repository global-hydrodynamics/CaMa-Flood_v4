# KG-0031: NetCDF SEQ with CF-derived start time is rejected during NFORCE validation

- Gap ID: `KG-0031`
- Linked event ID: `EV-0374`
- Category: NetCDF SEQ CF-time initialization
- Evidence basis: pre/post-run reproduction and source inspection
- Status: open

## What remains unclear?

The intended NetCDF `CROFFREQ="SEQ"` behavior allows the initial record time to come from CF metadata when the explicit start date is omitted. The tested configuration instead stops during NFORCE validation with `NetCDF SEQ date fields must be omitted when SYEARIN<=0.` Whether the maintainer wants this behavior corrected in a separate forcing task remains undecided.

## Verified facts

- A Mekong NetCDF SEQ configuration with `CROFCDF` and `CVNTIME="time"`, and without `SYEARIN`, `SMONIN`, `SDAYIN`, or `SHOURIN`, stopped with status 9 during `CMF_FORCING_NMLIST` in both the pre-refactor and refactored executables.
- In `src_main/cmf_ctrl_forcing_mod.F90`, omitted date fields are first changed to zero when `LSTART_DATE_SET` is false (lines 499–504). The subsequent CF-time SEQ branch checks whether `SMONIN`, `SDAYIN`, and `SHOURIN` differ from the sentinel `-9999` (lines 506–510); the assigned zero values therefore trigger the error.
- This behavior predates the readability refactor. It was preserved and not corrected in this task.

## Why the gap matters

Users may reasonably expect a NetCDF sequence with a valid CF time coordinate to start without explicit date fields. The current validation branch prevents reaching the existing CF-time-axis initialization for that configuration.
