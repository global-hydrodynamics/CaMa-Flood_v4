# HI-0015: Runoff time convention and local binary CTL correction

- Intervention ID: `HI-0015`
- Linked event ID: `EV-0233`
- Task ID: `DT-0036`
- Category: scientific convention and sample metadata clarification
- Maintainer review: pending

## Trigger

The tracked ERA5-Land binary CTL declared 62 daily records, while the 31 ignored local daily files each held two grids. The package Japan hourly sample also had a CTL unit comment that conflicted with the model run configuration.

## Maintainer instruction

The maintainer clarified that CaMa-Flood forcing dates follow the selected runoff dataset's timestamp convention. They identified the ERA5-Land CTL interval as erroneous, confirmed that the binary files were processed by the script workflow, requested the CTL correction and runoff registry update, and directed that the root Python setup script provide the pandas, xarray, and NetCDF4 conversion dependencies. They also directed inferring the `test_jpn_1hr` unit from `gosh/test3-jpn_fcast.sh`'s `DROFUNIT`.

## Result and limits

The ERA5-Land CTL/report were updated to 62 records at 12-hour spacing to describe the observed two-record-per-day local layout; binary files were not modified. The current tracked NetCDF sample and wrapper still specify 31 daily timestamps/24-hour processing, so the local binary layout is not reproducible from current tracked settings and its values remain unvalidated. `test_jpn_1hr` is registered as mm per 1-hour record based on `IFRQ_INP=1` and `DROFUNIT=3600000`; this is the configured conversion convention, not an independent validation of values. Existing root requirements already listed pandas, xarray, and NetCDF4; `s00-python_setup.sh` now checks those imports after installation.
