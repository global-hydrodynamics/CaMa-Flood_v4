# DR-0014: Make the bifurcation depth/width raster an opt-in check product

- Discussion ID: `DR-0014`
- Linked event ID(s): `EV-0100`, `EV-0101`
- Source type: Codex conversation
- Source reference: maintainer instruction in the active conversation, 2026-11-01; no stable archive ID
- Source access: restricted
- Maintainer review: pending

## Question and context

The shared v5 `param_set_bifparam` produced a two-record depth/width raster on every run under the legacy-like name `bifdph.bin`. The raster is intended for checking the derived bifurcation depth and width, not as a standard simulation input. Routine generation therefore created a diagnostic file that users could mistake for a normal model product.

## Evidence examined

- v5 shared source `map/tools/code/param_set_bifparam.F90` writes record 1 from `bifdph` and record 2 from `bifwth`; both are initialized to -9999 and have units of metres in the source comments.
- The old implementation under `map/src/src_param/set_bifparam.F90` writes `bifdph.bin`; it remains unchanged for v4 users.
- The v5 caller is `map/tools/script_params/s02-bifurcation.sh`; product metadata is in `map/map_variables.csv`.

## Alternatives discussed

Retain unconditional output under the old name; rename it while continuing unconditional output; or use an explicitly requested check-map option and a filename that identifies the file as diagnostic.

## Proposal (not yet a decision)

The maintainer proposed `check_bif_dphwth.bin` as a clearer filename and requested that the raster be written only when a `check_map` argument is supplied.

## Maintainer decision and rationale

Approved for the v5 shared tool: default execution omits the diagnostic raster; `check_map` explicitly requests it. The filename `check_bif_dphwth.bin` makes its inspection-only purpose clear and describes both stored fields. Keep the v4 `map/src/` implementation and its existing `bifdph.bin` behavior unchanged. The numerical derivation and two-record contents are unchanged.

## Implementation instruction, if any

Add an optional fifth argument `check_map` to the shared Fortran executable and expose it as the optional positional argument to the v5 `s02-bifurcation.sh` wrapper. Without the token, do not write the check raster. With it, write `check_bif_dphwth.bin`, depth first and width second. Keep the ordinary `bifprm.txt` and basin/connectivity workflow outputs unchanged. Update the variable registry and v5 workflow documentation; preserve pre-existing map files.

## Outcome or unresolved questions

The shared program and both current v5 wrappers, the registry, workflow documentation, and branch-local project status were updated in the worktree. No model simulation or automated test was run for this task. The previous B2.3 byte-comparison record describes the earlier behavior and remains historical evidence; it does not validate the new opt-in argument path.
