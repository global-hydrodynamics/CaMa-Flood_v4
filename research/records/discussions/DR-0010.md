## Approved decisions and rationale

- Centralize shared Fortran sources and executables in `map/tools/code/` behind one Makefile, and use map-local shell templates that invoke those tools. The approved architecture explicitly excludes map-local builds and duplicated Fortran copies in v5 target workflows.
- Organize v5 `script_params/` by preferred map-preparation sequence: `s01` channel parameters, `s02` bifurcation, `s03` user-configured input matrix, `s04` MPI setup, and `s05` permanent water, with gauge/dam allocation as `t` scripts. This sequence describes product workflow order; it does not make every stage mandatory.
- Keep annual mean discharge, power-law cross-section parameterization, and MERIT Hydro width merging in the new `s01` recipe. Separate bifurcation, general input-matrix generation, MPI preparation, and permanent-water generation because they are distinct products and workflows.
- Keep `region_default_inpmat` separate from `param_generate_inpmat`: the former creates the standard map-distributed matrix for standard annual runoff and channel-parameter estimation; the latter constructs a mapping for user-selected runoff grids. The channel workflow should reuse the existing standard matrix rather than regenerate it.
- Use the clearer v5 names `param_set_merit_width` and `rivwth_merit.bin` for the MERIT Hydro/power-law merged width, while retaining `width.bin` as input and `rivwth.bin` / `rivhgt.bin` as power-law outputs. The maintainer explicitly approved the filename/interface distinction, not a numerical change.
- Preserve existing v4 scripts in `gosh/` and sources/workflows in `map/src/`. This continues the established backward-compatibility boundary for existing package users and concurrent contributions; prior rationale is also recorded in `DR-0003`.
- Retain `calc_outclmday.F90` only as historical legacy code. The maintainer associates it with the older maximum-30-day climatology approach described in Yamazaki et al. (2011) and reports that later evaluation favored annual mean runoff. This migration does not independently validate that scientific comparison.
- Preserve the maintainer-organized `map_variables.csv` fields and category assignments: category IDs follow map-product processing order, 10–19 are default/distributed or regionalization products, 900–999 are high-resolution products, and other parameter/auxiliary categories continue to be organized during migration.

## Implementation boundaries

This task migrates only `calc_outclm`, `calc_rivwth`, and `set_gwdlr`, adds the v5 `s01-channel_params.sh`, and renames the v5 general matrix wrapper from `s02-generate_inpmat.sh` to `s03-generate_inpmat.sh`. No bifurcation, MPI, permanent-water, allocation, or analysis workflows are implemented here. Legacy names and scientific calculations remain unchanged.

## Input-data decision

The standard ELSE_GPCC runoff file is available in the inspected v4.30 data package and is described by the package guide as based on ELSE_GPCC (Kim et al., 2009). No explicit redistribution terms were found in the available local documentation. The source file was used read-only in temporary regression work and was not added to GitHub; a maintainer/license decision is needed before redistribution.
