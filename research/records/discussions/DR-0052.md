## Alternatives discussed

- **Restart:** removing NetCDF's current-outflow copy would align it with the former Binary initialization but discard the restored last-step values from current state. The implemented choice retains the NetCDF behavior and aligns Binary to it for Normal Restart. Storage-only remains distinct because a data-assimilation product may contain updated storage without the prior-step flow state needed for an exact continuous restart.
- **High-resolution conversion:** uncompressed output or a higher default deflate level were not selected. The accepted goal prioritizes smaller files while retaining exact source values; level 3 plus shuffle/deflate is the standard, and independent file tasks are processed by Python workers to improve throughput on large tile sets.
- **Testing:** repeatedly testing zlib/HDF5/NetCDF's internal lossless algorithms was rejected. Tests instead check CaMa-Flood's inputs to those libraries, stored type/layout/coordinates, conversion values and worker/error behavior. Individual development uses focused checks; pre-merge review uses broader relevant build/regression/integration checks, with full-package or global-scale runs reserved for risks that justify them.

## Maintainer decision and rationale

Normal Restart represents time-continuous continuation and restores the preceding-step state. Storage-only Restart is intended for data-assimilation workflows, including Kalman-filter updates to available storage fields when prior-step flows are unavailable; it starts a new trajectory and does not promise equality with the original continuous run. Optional groundwater delay, reservoir, levee, and bifurcation schemes contribute state conditionally, so Binary record positions depend on enabled schemes and Restart mode. Binary uses ordered direct-access records (with the bifurcation companion in `.pth`), while NetCDF selects named Float64 variables.

For Normal Restart, current outflow initialization should match across formats. The maintainer's pushed correction assigns the restored `D2RIVOUT_PRE` and `D2FLDOUT_PRE` values to their current arrays in the Binary reader, retaining the existing NetCDF behavior. The previous two-year comparison predates this correction; a post-fix diagnostic/runtime validation has not been recorded. The maintainer subsequently confirmed that a separate runtime test is not required for this implemented behavior, so this remains an unmeasured effect rather than an outstanding test task.

For high-resolution map distribution, the output-size priority favors lossless zlib/deflate compression with shuffle at default level 3. Python's `JOBS`-bounded process pool runs independent variable/tile conversions; Shell scripts expose the simple `JOBS` setting and pass it to Python. Binary data, types, records, coordinates, and missing-value semantics remain unchanged.

Testing is directed at CaMa-Flood's scientific calculations and interfaces rather than revalidating guarantees provided by external dependencies. Validation is proportional during implementation, then broadened to relevant combinations and workflows before PR/merge. This does not make an unrelated global-scale run mandatory for every change.
