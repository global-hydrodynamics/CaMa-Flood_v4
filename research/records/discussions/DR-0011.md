## Question and context

Review identified edge-case concerns in the `near` runoff interpolation path in `param_calc_outclm`. The standard v5 channel-parameter wrapper selects `inpmat`.

## Evidence examined

- `map/tools/code/param_calc_outclm.F90` branches on `INTERP` and calls `conv_resol` for `near`, otherwise `intp_roff` with the matrix.
- `map/tools/script_params/s01-channel_params.sh` sets `INTERP="inpmat"`.

## Alternatives discussed

- Modify or remove the optional `near` path while reviewing its edge cases.
- Retain it unchanged because it is a precautionary option and is not used by the standard workflow.

## Proposal (not yet a decision)

Retain the existing implementation and keep the standard wrapper on the matrix-based path.

## Maintainer decision and rationale

The maintainer confirmed that nearest-grid is included as a precautionary option and is not used by default. The existing implementation should remain unchanged.

## Implementation instruction, if any

Do not modify the `near` calculation as part of the current review. The standard `s01` workflow continues to use `inpmat`.

## Outcome or unresolved questions

The optional path's edge cases remain unmodified and are outside the standard workflow. This decision does not establish that every `near` configuration is valid.
