# DR-0055: Standardize lossless NetCDF compression and simplify Forcing internals

- **Events:** EV-0345 (maintainer instruction), EV-0346 (implementation), EV-0347 (validation)
- **Source:** Maintainer task instruction in the active Codex conversation, 2026-11-04; no stable archive ID
- **Review status:** Pending maintainer review of this AI-authored summary
- **Source access:** Restricted conversation context; implementation and test evidence are repository-observable

## Question and context

How should newly generated NetCDF files in active CaMa-Flood v5 tools be compressed while preserving established data contracts, and what final simplifications are safe in the CROFFREQ-based Forcing module?

## Evidence examined

- Active NetCDF writers under `src_main/`, `map/tools/`, and `inp/`, plus the classic-format channel-parameter writer.
- `src_main/cmf_ctrl_forcing_mod.F90`, `src_main/FORTRAN_STYLE.md`, the model and tool READMEs, and the existing CROFFREQ implementation history.
- Focused Binary and NetCDF builds, a representative Mekong map conversion, a temporary exact-value runoff conversion, one-day NetCDF forcing model run, map workflow tests, and CF-time tests; see VR-0109.

## Alternatives discussed

The instruction specified level 3 and excluded lossy encoding, scale/offset transformations, reduced precision, and quantization. It did not record a comparison among compression levels. The established NetCDF classic 64-bit-offset channel-parameter output remains an exception because that format does not support NetCDF-4 deflate filters.

Repeated interval checks in the shared grouped-file resolver and the cached grouped NetCDF path duplicated invariants already guaranteed by Namelist validation or the resolver itself. Keeping every repeated check was unnecessary; checks for Binary/NetCDF SEQ time alignment, CF-time validation, file-period boundaries, and I/O errors remain.

## Maintainer decision and rationale

Newly generated active v5 NetCDF-4 data should use lossless zlib/deflate level 3 and shuffle where supported, without changing numeric precision, data values, dimensions, variable order, metadata, or scientific meaning. Existing files are not automatically rewritten, external NetCDF inputs are not required to use this compression, and compatibility-required format exceptions remain documented.

Forcing remains governed by the already approved CROFFREQ interface: DAY/MON/YEAR are standard period-start formats, while SEQ is an advanced single-file mode. The final cleanup should remove only duplicate validation and logging, clarify the record-index and CF-time contracts, organize principal and utility procedures, and explicitly reject `LINPCDF=.TRUE.` in a Binary-only build. It must not change runoff calculations, units, LROSPLIT, CF-time behavior, or LWEVAP semantics.

## Implementation instruction, if any

The maintainer authorized the described code, documentation, and focused test changes on `feature/gosh-refactor`, with commits and a normal push. Historical v4 writers and archived workflows were to remain unchanged.

## Outcome or unresolved questions

Active writers were updated, with the NetCDF classic channel-parameter writer documented as the format exception. The Mekong sample converter now creates NetCDF-4 and uses `nccopy -d 3 -s`, then verifies exact Float32 runoff values. The Forcing module dropped duplicate grouped interval checks and one duplicate log, clarified SEQ and period indexing, and now rejects NetCDF forcing in a Binary-only build. No scientific calculation or input value semantics changed.

The ERA5-Land Python writer's runtime compression assertion could not run because xarray/NetCDF4 dependencies are unavailable in the environment. The existing LWEVAP path still expects a third forcing field although the current runoff reader does not populate one; it was inspected and intentionally left unchanged. Validation limits are recorded in VR-0109.
