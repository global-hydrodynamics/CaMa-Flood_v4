## Question and context

How should future CaMa-Flood v5 architecture work remember the intended distinction between the external Coupler role and the internal Driver role, and the need for more flexible Driver responsibilities?

## Alternatives discussed

The maintainer identified two future options for the HeatLink use case: a dedicated HeatLink Coupler, or greater flexibility in the standard Driver so the Coupler can control operations such as Restart timing. No option was selected.

## Proposal (not yet a decision)

Before implementation, map dependencies among forcing updates, adaptive advancement, physics, output, Restart, and time updates; compare the coupling options; define compatibility and validation requirements.

## Maintainer decision and rationale

The maintainer confirmed the direction to preserve `MAIN_cmf.F90` as the Standalone Coupler reference, support custom Couplers using the existing Driver entry points as a future goal, and investigate more flexible Driver coordination while preserving scientific order. HeatLink's synchronized Restart requirement is a motivating example. Specific interfaces, implementation, and timing remain undecided.

## Implementation instruction, if any

Documentation only. Do not refactor MAIN/DRV, change Restart behavior, modify HeatLink, or add a Coupler interface as part of this record.
