# DR-0057: Bifurcation simulation input and state identity

- **Discussion ID:** DR-0057
- **Linked event IDs:** EV-0363; EV-0364; EV-0365
- **Source type:** Maintainer implementation instruction and source/data review
- **Source reference:** Active Codex conversation and attached task; no stable archive ID
- **Source access:** restricted
- **Maintainer review:** pending

## Question and context

The v5 map workflow now produces an authoritative named `bifprm.csv` and a NetCDF-4 representation. Model execution previously still depended on the legacy positional TXT table. The integration must preserve established hydraulic calculations while making the finalized table formats usable by simulation, output, and Restart.

## Evidence examined

The existing model had a TXT reader in `READ_BIFPARAM`, a path-shaped Binary `.pth` flow layout, NetCDF `pthflw_pre` with path and layer dimensions, and a single `YOS_CMF_MAP` location for numerical pathway arrays. The generated Mekong files contain 382 paths and five layers. `bifori.txt` stores source coordinates with a header/reader ordering discrepancy already described in the map metadata specification. The model-side change retains the established reader interpretation.

## Alternatives discussed

- Continue using only the legacy TXT table in simulation.
- Replace the model input with NetCDF only.
- Accept CSV as the authoritative v5 source, accept its NetCDF representation when NetCDF support is compiled, and preserve TXT compatibility.
- Put complete static path parameters into Restart files, or only enough path identity to validate stored bifurcation flow ordering.

## Maintainer decision and rationale

The maintainer approved three input formats: CSV, NetCDF, and legacy TXT, selected by the `CPTHOUT` filename suffix. CSV remains authoritative; NetCDF conversion does not change path ordering or scientific values; TXT remains available for old configurations. Complete path metadata belong with scientific `pthflw` output, while Restart receives only `pth_id` and endpoint indices because it is a state-continuation artifact. Binary Restart layout remains unchanged.

## Implementation instruction, if any

Use shared CSV parsing helpers from `cmf_utils_mod`; keep format-specific reads separate from common hydraulic initialization. Do not alter the bifurcation calculations, output averaging, MPI aggregation, or Binary record structure. Mekong `mek01` uses CSV and `mek02` uses NetCDF. Compare represented numerical outputs with suitable tolerances where conversion precision differs.

## Outcome or unresolved questions

The implementation and focused Mekong checks are recorded in VR-0115. Source/header interpretation for the final `bifori.txt` coordinate pair remains unresolved and was not changed. Binary Restart continues to rely on matching path order because adding identity metadata would change its established format.
