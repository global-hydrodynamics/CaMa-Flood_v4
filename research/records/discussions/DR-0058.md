# DR-0058: Store bifurcation NetCDF under map/netcdf

- **Discussion ID:** DR-0058
- **Linked event:** EV-0366
- **Source:** Maintainer task attachment in the active Codex conversation, 2026-11-05; no stable archive ID
- **Access:** Restricted source; this public record contains a reviewed summary only
- **Review status:** Pending maintainer review

## Question and context

The maintained v5 parameter workflow previously wrote both authoritative `bifprm.csv` and its NetCDF representation `bifprm.nc` in the map root. The Mekong map already uses `<MAPDIR>/netcdf/` for NetCDF map products. The maintainer requested moving only the NetCDF bifurcation table into this directory while keeping the CSV authoritative at the map root.

## Evidence examined

The s02 scripts pass an explicit output path to the standalone CSV-to-NetCDF converter. The Mekong `bifprm.nc` existed as a tracked sample. The maintained `mek02` sample uses the map NetCDF directory, while `mek01` selects `bifprm.csv`. Regression tests compare the generated NetCDF table with the CSV.

## Alternatives discussed

No alternatives were recorded in the approved task. The standalone converter remains location-agnostic and continues to default to a NetCDF file beside its CSV when no output path is supplied.

## Maintainer decision and rationale

Store the workflow output as `<MAPDIR>/netcdf/bifprm.nc`, alongside other map NetCDF products, and retain `<MAPDIR>/bifprm.csv` as the authoritative parameter table. This is a file-organization decision; it does not change scientific values, format schema, or converter behavior.

## Outcome or unresolved questions

Implementation and validation are recorded in DT-0071 and VR-0116. No material scientific question was raised by this relocation.
