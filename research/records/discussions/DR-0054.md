# DR-0054: Make CROFFREQ the sole v5 forcing grouping setting

## Question and context

Should CaMa-Flood v5 preserve the earlier `LINPDAY` compatibility path alongside `CROFFREQ`, or simplify the Namelist to one explicit setting for forcing file grouping? The maintainer chose the simpler interface and also clarified the temporal contract for grouped forcing files.

## Evidence examined

- `src_main/cmf_ctrl_forcing_mod.F90` for the Namelist, Binary and NetCDF file selection, record indexing, and NetCDF CF time validation.
- `src_main/common/cmf_cf_time_mod.F90` for the CF coordinate and interval-boundary resolver used by NetCDF forcing.
- `inp/README.md`, `inp/runoff_datasets.csv`, `inp/validate_runoff_datasets.py`, and active `gosh_sample/` configurations for user-facing settings and examples.
- Focused Binary and NetCDF builds and temporary reader/configuration harnesses recorded in VR-0108.

## Alternatives discussed

Keeping `LINPDAY` as a second selector would retain compatibility behavior and require distinguishing omitted settings from explicit values. A custom scan of Namelist text was used to detect that distinction. The maintainer instead selected one required grouping parameter and ordinary Fortran Namelist error handling, so old unknown `LINPDAY` entries fail clearly.

A configurable first-record offset for DAY/MON/YEAR was also considered unnecessary. These standard formats derive the file period from its name and index records from that period's beginning. Arbitrary offsets remain confined to the advanced SEQ mode.

## Maintainer decision and rationale

`CROFFREQ` is the sole required v5 grouping setting, with `DAY`, `MON`, `YEAR`, and `SEQ` as accepted values. Removing `LINPDAY`, `LCROFFREQ_EXPLICIT`, and the custom Namelist text parser makes configuration unambiguous and uses the compiler's standard `IOSTAT`/`IOMSG` error reporting for unknown fields.

DAY, MON, and YEAR are the recommended standard formats. The filename identifies the calendar period, and its first record represents 00:00 at the start of that period. Explicit `SYEARIN`, `SMONIN`, `SDAYIN`, or `SHOURIN` settings are rejected for these modes. NetCDF grouped files require CF time metadata; the implementation verifies the requested times and confirms that record 1 or its CF interval lower bound begins at the named period boundary.

SEQ remains an advanced/legacy option. Binary SEQ requires all four first-record date fields because Binary has no time coordinate. NetCDF SEQ continues to use either its CF time coordinate or the existing explicit first-record datetime. Users are responsible for supplying complete, correctly aligned SEQ files; no extra Binary file-length preflight is performed. Normal file I/O errors report missing or truncated records.

`IFRQ_INP`, `DROFUNIT`, `LINPCDF`, `LROSPLIT`, and runoff calculations retain their separate roles. This decision changes the forcing configuration and file-time contract, not scientific runoff computation or unit conversion.
