# DR-0053: Separate runoff file grouping from format and timestep

## Question and context

How should the runoff reader support daily, monthly, annual, and continuous forcing files without conflating file grouping with Binary/NetCDF format, forcing interval, or unit conversion?

## Evidence examined

- `src_main/cmf_ctrl_forcing_mod.F90` and the existing NetCDF CF-time resolver for file opening, record indexing, and format-specific behavior.
- `src_main/cmf_ctrl_time_mod.F90`, `src_main/cmf_utils_mod.F90`, `src_main/yos_cmf_time.F90`, and `src_main/yos_cmf_input.F90` for model-calendar, elapsed-minute, forcing-interval, and leap-year handling.
- `gosh_sample/mek01-default_run.sh`, annual NetCDF samples, `inp/test-mek_1deg_nc/`, and `inp/runoff_datasets.csv` for current operational examples.

## Alternatives discussed

- Daily-only files and a single sequential time-series file were the existing choices. The maintainer authorized adding `DAY`, `MON`, and `YEAR` alongside `SEQ`, with the first three as recommended standards and `SEQ` retained as a legacy/advanced mode.
- Duplicating date arithmetic in the Forcing module was rejected. The implementation reuses `MIN2DATE`, `DATE2MIN`, and `IMDAYS`, keeping `LLEAPYR` as the model calendar authority.
- Filename discovery or arbitrary filename templates were excluded; grouping inserts only the canonical date tag between the configured prefix and suffix.

## Maintainer decision and rationale

The instruction separates four independent properties: input format (`LINPCDF`), grouping (`CROFFREQ`), record interval (`IFRQ_INP`/`DTIN`), and unit conversion (`DROFUNIT`). `CROFFREQ` is explicit when supplied. If omitted, old behavior remains: Binary daily files; NetCDF daily files for `LINPDAY=.TRUE.` and one sequence file for `.FALSE.`. An explicitly present contradictory `LINPDAY` and `CROFFREQ` is a configuration error. Binary SEQ requires all four first-record date fields because the format has no time metadata; Binary DAY/MON/YEAR remain anchored to model-calendar boundaries and ignore these fields. NetCDF SEQ retains `CROFCDF` and existing CF or explicit-start behavior.

Calendar-grouped files use record indices measured from midnight at the period start, require integer-hour forcing intervals that divide 24 hours, and use model time conversion to normalize requested timestamps. Binary has no calendar metadata; users must align its records with `LLEAPYR`. Existing CF checks remain the source of NetCDF calendar, interval, ordering, coverage, supported-unit, and optional time-bound validation when automatic CF time resolution is selected. File handles are cached and switched at grouping boundaries.

The implementation deliberately leaves runoff mapping, interpolation, and unit conversion algorithms unchanged. `LWEVAP` remains a known limitation: the existing reader path does not populate a third evaporation field even though `CMF_FORCING_PUT` expects one when enabled. This task does not silently alter that optional path.
