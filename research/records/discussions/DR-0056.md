# DR-0056: Bifurcation parameter CSV/NetCDF migration

- **Discussion ID:** DR-0056
- **Linked event IDs:** EV-0360; EV-0361; EV-0362
- **Source type:** Maintainer implementation instruction and source review
- **Source reference:** Active Codex conversation; no stable archive ID
- **Source access:** restricted
- **Maintainer review:** pending

## Question and context

The v5 map-preparation workflow and its serial/MPI consumers used a positional text table. The approved migration calls for named, portable map products while leaving current simulation readers and the historical v4 tree untouched.

## Evidence examined

The legacy generator reads each `bifori.txt` record in source order, filters by the configured width-layer count, calculates the existing bifurcation depth, and writes the retained rows. No separate sort exists in the standard generator. MPI preprocessing has its own order-sensitive sort by basin IDs and elevation with a deterministic legacy-row tie-break. `lonlat.bin` stores outlet longitude in record 1 and latitude in record 2.

The inspected `bifori.txt` header labels the final coordinate pair `(lon,lat)`, while both the existing and migrated generators read those fields into `lat,lon`; the Mekong sample matches the established legacy `bifprm.txt` values under that interpretation. The header/reader discrepancy remains unresolved and was not silently reinterpreted.

## Alternatives discussed

- Add NetCDF dependencies and writing to the scientific Fortran generator.
- Generate one finalized named CSV in Fortran, then use an independent reusable converter for NetCDF.
- Preserve an old text file as an implicit compatibility fallback.

## Maintainer decision and rationale

The maintainer selected the independent converter approach to keep scientific parameter generation separate from format conversion and avoid NetCDF dependencies in the Fortran generator. Work remains on `feature/gosh-refactor`; edits remain limited to `map/`, the map-variable registry/docs, and research records.

## Implementation instruction

`param_bif_set_params.F90` emits the finalized CSV only. The converter reads it without recalculation, filtering, or reordering. s02 executes generation, conversion, then basin processing. v5 serial basin, MPI basin, and MPI connectivity diagnostic tools consume CSV by named columns. Existing simulation readers and legacy map tools remain unchanged.

## Outcome or unresolved questions

The map workflow now produces `bifprm.csv` and `bifprm.nc`; both preserve the finalized retained path rows and the NetCDF uses `path` and `layer` dimensions (`width(layer,path)`). The model runtime still consumes legacy `bifprm.txt`, so integration is intentionally incomplete until a separate model-side task. The source header-versus-reader coordinate-label discrepancy remains for maintainer/source-producer clarification.
