## Question and context

The maintainer observed that `catmpx.bin` and `class.bin` were absent from the generated `mekong_15min` sample, and requested checking whether they exist in the global map and whether the regionalization workflow should carry them. The follow-up asked to trace their original meanings in the private FLOW `src_conv` producer code and update `map/map_variables.csv`.

## Evidence examined

- `FLOW/src_conv/upscale_flwdir.f90` initializes the output `catmpx` to `-9999`, assigns `locupg` at selected unit-catchment outlets, and writes per-tile `catmpx` and `class` records.
- `update_locupg` counts high-resolution pixels along flow paths, with outlet handling and accumulation adjustments. The writer labels the result “number of catchment pixel”.
- `FLOW/src_conv/merge_rivmap.f90` merges the records into global files. It documents the stored class codes as `0=land, 1=lake, 3=river center, 4=river non-center, 6=glacier`.
- The `upscale_flwdir.f90` inline comment describes code 4 as “river center”, conflicting with the merge comment and the maintainer-confirmed legend.
- Both files are present in the inspected `glb_15min` data and in the maintainer-generated local `mekong_15min` sample. The shared v5 crop code treats both as optional int32 rasters and preserves their values when present.

## Alternatives discussed

- Infer meanings from filenames or GrADS CTL labels. This was not sufficient because the available CTL labels are generic.
- Use the producer/merge implementation and maintainer's explicit class legend. This provides direct evidence for the data meaning and is the basis used in the registry.

## Proposal (not yet a decision)

No separate design proposal was made. The task was to establish existing semantics and record them in the common map-variable registry.

## Maintainer decision and rationale

The maintainer supplied the class legend `0=land, 1=lake, 3=river center, 4=river non-center, 6=glacier`. This confirmed definition was followed because it agrees with the merged-map comment in `merge_rivmap.f90`; the contradictory inline comment in `upscale_flwdir.f90` remains documented as a source discrepancy. Existing category IDs were preserved.

## Implementation instruction, if any

Update `catmpx` and `class` metadata in `map/map_variables.csv`, including current sample availability and `workflow_stage=default` for products now present. Preserve the category IDs and all existing user-generated sample files. The `catmpx` description records a count of high-resolution pixels in the unit catchment; `class` records the confirmed categorical legend and does not infer a stored missing sentinel from the CTL `undef` declaration.
