## Approved scope

Migrate only the general `map/src/src_param/generate_inpmat.F90` program and its `s02-generate_inpmat.sh` workflow to the approved shared-code/map-local-wrapper architecture. Keep the legacy v4 source and scripts unchanged, keep `region_default_inpmat` separate, and do not migrate other parameter, allocation, or analysis tools. No merge, rebase, force-push, or unrelated registry reorganization is authorized.

## Implementation boundary

The shared source is a direct copy under the new name `map/tools/code/param_generate_inpmat.F90`; algorithm, argument order, numerical precision, file layout and output metadata must remain unchanged. The existing unified Makefile wildcard for `param_*.F90` makes `param_generate_inpmat` available through the `param` target; no Makefile rule change is required. The new wrapper retains the legacy example's runoff grid, outputs, and default high-resolution tag preference, while resolving shared code and map-root CWD from its map-local location and checking executable and input availability.

The general utility constructs an area-overlap mapping for user-selected regular runoff-grid geometry; it does not read runoff values. It is not interchangeable with `region_default_inpmat`, which generates a fixed standard map-distributed climatology matrix.

## Validation and limits

The two executables were compared using the Mekong map inputs in temporary directories. Dimension metadata and the complete binary matrix were byte-identical under the same compiler and configuration. This supports mechanical migration compatibility for the tested sample only; it is not model/scientific validation and does not cover every grid, high-resolution layout, or fallback branch. See `VR-0025`.
