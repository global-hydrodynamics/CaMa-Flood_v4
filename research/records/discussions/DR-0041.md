# DR-0041: Make legacy river-analysis tools discoverable through v5 workflows

- Discussion ID: `DR-0041`
- Linked event IDs: `EV-0207`–`EV-0210`
- Source type: Maintainer task and approval in active Codex conversation
- Source reference: Phase C task attachment plus maintainer answers authorizing a v5-only subbasin index guard and optional paired output paths
- Source access: restricted for the instruction; implementation and tests are public repository artifacts
- Maintainer review: pending

## Question and context

Three useful river-network utilities existed only under `map/src/src_param/`, making river-cell inspection, upstream-mask generation, and subbasin segmentation difficult for users to discover and reproduce. The task separates standard map-preparation products from exploratory analysis while preserving legacy v4 source and behavior.

## Evidence examined

- Legacy sources: `map/src/src_param/get_rivinfo.F90`, `get_upbasin.F90`, `get_subbasin.F90`.
- Migrated implementations and wrappers: `map/tools/code/analysis_get_*.F90`, `map/tools/script_params/s06-subbasin.sh`, `s07-upbasin.sh`, and `map/tools/script_analysis/a01`–`a03`.
- Mekong map's `GRDC_alloc.txt`; the allocated primary grid indices differ from a fresh lat/lon re-query in the example examined.
- Six focused regression tests compile v4/v5 tools and operate only on temporary map copies.

## Alternatives discussed

- Keep the utilities only in the historical tree, preserving their existing poor discoverability.
- Add shared v5 programs and both standard-product and configurable-analysis entry points, without duplicating scientific calculations.
- Use a primary station cell for the GRDC example or remap its reported coordinates. The task specifies the allocated primary cell; remapping could select a different cell.

## Maintainer decision and rationale

The approved sample threshold for s06 is 50,000 km2. It is a practical demonstration setting and is not a scientifically calibrated universal threshold. The GRDC demonstration uses the valid allocation with the largest positive `area_CaMa`, breaking ties by first file order, and uses the allocated `ix1,iy1` cell. For multi-catchment allocations, this single-cell upstream mask is not asserted to represent the full allocated drainage area.

The maintainer approved a v5-only check that avoids using invalid downstream indices in the subbasin-area comparison. The maintainer also approved a backward-compatible optional pair of output filenames for `analysis_get_subbasin`, so exploratory runs can avoid replacing the standard `subbsn.bin` and `subcol.bin`. The preserved v4 sources were not changed.

## Implementation instruction

Keep standard outputs under `script_params/` and arbitrary diagnostic runs under `script_analysis/`. Build scientific executables centrally in `map/tools/code/`; do not duplicate the Fortran algorithms or add an independent CTL writer. Keep the standard registry rows and allow automated CTL generation only for registered names.

## Outcome or unresolved questions

The selected Mekong record is GRDC ID `2569002`, allocated primary cell `(62,93)`, `area_Input=663168.75 km2`, `area_CaMa=663000.25 km2`, and `Type=1`. Regression tests show exact v4/v5 equality for the tested river-info text and raster outputs, plus successful bounds-checked v5 execution. No independent scientific validation of the threshold, river-network segmentation, or individual gauge allocation was performed. `get_vecmap` remains deferred.
