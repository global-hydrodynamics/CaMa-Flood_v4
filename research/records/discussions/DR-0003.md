## Scope and chronology reconstructed from evidence

The maintainer authorized an independent v5 regional workflow under `map/tools/`, while preserving legacy v4 regional sources and excluding CTL generation and map-data execution from that task (EV-0020). The implementation added five regional Fortran programs, a script template, shared build machinery, and READMEs (EV-0021). The work was committed with the existing documentation/metadata at `ad7d544` on 2026-10-30. Later commits `c2b1aac` and `ea14d6b` refined map registry, workflow guidance, tests and CI; they are not evidence that the full regionalization algorithm was scientifically validated.

The build design passed through three recorded placements. EV-0023/24 specify a unified Makefile, `region_`/`param_` naming and a map-specific build output. EV-0026/27 move executables into each map-local `script_region/`. EV-0029/30 establish explicit builds into shared `map/tools/code/`, with map-local workflows calling those shared executables while retaining their current directory for relative data paths. The final arrangement is documented in the source and templates. The contemporaneous records preserve what changed, but not all decision rationales.

VR-0005 through VR-0008 record successful GNU Fortran compilation and static/shell checks in temporary repository-shaped trees. They include source-copy comparisons and checks of build/clean behavior, paths, and missing-executable handling. The available `ifort` attempt was inconclusive because of compiler flags and SDK discovery in the environment. Those validations did not run the v5 regional programs on map data and did not assess scientific correctness.

The existing human-intervention record HI-0001, linked to EV-0017, refers to the maintainer-reported execution of the legacy v4 `map/mekong_15min/src_region/s01-regional_map.sh`. It should remain separate from the v5 workflow. The contemporaneous B1 validation notes through VR-0008 say that no v5 map-generation run had occurred at that point.

A retrospective read-only inspection found current untracked Mekong files `script_region/region_info.txt`, `script_region/dim_change.txt`, `catmpx.bin`, `class.bin`, and `class.ctl` with modification times after VR-0018. Their settings show `../../glb_15min/` and 90–110°E, 5–35°N. This is recorded as a present-worktree observation only: timestamps and contents do not identify who ran a script, the exact code revision, whether a full run succeeded, or whether the output was accepted. No new human-intervention or validation claim is made from these files alone.

## Decisions and implementation facts

- The v5 regional workflow is a parallel source tree; this task's scope explicitly kept legacy v4 sources unchanged.
- Five current regional Fortran source files were copied into `map/tools/code/`; VR-0005 reports byte comparisons with `map/src/src_region/`.
- The final build uses explicit Makefile targets and one shared executable location. Map-local scripts do not compile the tools and must be run with their map-local directory as the working directory.
- CTL generation and actual map processing were excluded from the original B1 implementation task; CTL generation was later handled as a separate phase.

These are evidence-backed decisions and behaviors. No additional rationale is inferred here.
