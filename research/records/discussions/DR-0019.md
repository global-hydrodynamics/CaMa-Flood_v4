## Maintainer decision

`map/src/` contains the old v4 tools and is to be preserved as the historical legacy implementation. Future v5 migration and development belongs under `map/tools/`; legacy regional and MPI scripts using `diminfo_` are intentionally retained, not an unfinished migration. This resolves the apparent pending work described at the end of the prior ROFFTAG task.

The maintainer also confirmed that the standard non-MPI bifurcation work is at a phase boundary. Phase B2.3 covers the shared v5 programs, `s02-bifurcation.sh`, optional diagnostic outputs, related metadata/documentation, and the Mekong migration regression. MPI migration remains a separate future v5 task. This closure does not claim scientific validation or completion of all Phase B2 utilities.

## README and code review

The v5 overview and parameter workflow README already described standard outputs, the `check_map` products, stale diagnostic behavior, separation from MPI, and compatibility regression limits. They were updated to state the `BIFLAYER` clamp behavior and the visualization palette fallback. The source shows that `param_set_bifparam` warns and clamps a requested layer count to the number in `bifori.txt`; the basin listing prints no more than 20 active basins; if all palette colors 2–10 are occupied by neighbors, the basin visualizer assigns color 10 again. The last behavior may make adjacent regions share a display color, but it does not affect hydrological outputs.

Review also found stale `map/README.md` references to `map/src/map_data_tools/` and `map/src/src_param/native_inpmat/`, neither of which exists in the current tree. The overview was corrected to describe the present `map/tools/code/generate_ctl.py` CTL workflow and to avoid claiming that a binary-to-NetCDF converter is available. This aligns the navigation with the preserved v4 `map/src/` directories and active v5 tools.

## Remaining limitations and questions

No reproducible bifurcation defect was identified in the reviewed v5 standard path. The focused regression compares Mekong v5 outputs with legacy output records in temporary workspaces. It does not establish scientific correctness, cross-map or cross-compiler behavior, or MPI behavior. The current bifurcation test does not specifically exercise the fewer-source-layers clamp, the fewer-than-20-basin diagnostic limit, or exhausted-palette fallback. These are coverage gaps, not observed failures.

A separate ROFFTAG task had modified six `map/src/src_param/` shell templates before the maintainer clarified the preservation policy. Those six files were restored to their original `HEAD` versions, so the historical v4 tree is clean. ROFFTAG naming remains in the v5 workflows under `map/tools/`.
