# DR-0029: Separate MPI basin-color and region-color products

## Question and context

An earlier MPI workflow decision placed an MPI-region display map in the normal s04 workflow. The maintainer clarified that MPI-specific basin aggregation and computational-region partitioning are separate operations and need distinct visualization products.

## Evidence examined

The v5 basin aggregator produces the merged basin-ID raster before region partitioning. The partitioner consumes those IDs and emits `mpireg-N.bin`. The shared `map_color_mod::color_map` routine can be applied to either raster, but the resulting products have different meanings. `analysis_mpi_region_color` accepts a selected region map and writes the corresponding `bsncol_mpi-N.bin`.

## Alternatives discussed

- Keep region coloring in s04: rejected because it conflates a partition visualization with basin aggregation and adds an unnecessary automatic output.
- Generate `bifcol_mpi.bin` during basin aggregation and retain region coloring as a separate manual analysis: approved.

## Proposal (not yet a decision)

No open proposal remains for this task; the maintainer supplied the design as an approved instruction.

## Maintainer decision and rationale

`param_mpi_set_basin` writes `bifcol_mpi.bin` from the MPI-aggregated basin IDs once per aggregation run, independent of process count N. Its colors may vary with `normal` versus `MaxMPI` because those modes can form different basins. `param_mpi_set_region` writes only numbered `mpireg-N.bin` maps and performs no coloring. `analysis_mpi_region_color` remains available for optional manual creation of `bsncol_mpi-N.bin`; s04 does not invoke it. The existing shared color-assignment algorithm is retained unchanged. This supersedes the earlier automatic region-color output responsibility recorded in DR-0027; it does not rewrite that historical record or change the color algorithm.

## Implementation instruction, if any

Update the shared Makefile dependency, common and Mekong s04 scripts, registry metadata, directly affected documentation, and focused tests. Preserve basin-merging and region-partitioning algorithms, historical `map/src/`, model `src/`, `gosh/`, and current user changes. Keep the maintainer-controlled `workflow_stage` values in `map_variables.csv` unchanged.
