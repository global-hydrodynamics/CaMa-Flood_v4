## Approved project boundary

The maintainer approved a dedicated feature/gosh-refactor branch based on the latest origin/master, with no Issue for this project. The project establishes src_main/ and gosh_sample/ and migrates source and simulation workflows incrementally. The existing src/ and gosh/ trees are frozen legacy references and must remain unchanged.

The maintainer clarified that the initial copy must retain every source and workflow subdirectory and file, including ICI/, sediment/, and heatlink/; do not select or remove features at copy time. Bifurcation is a standard CaMa-Flood capability and must be enabled in the first Mekong run. The v5 build should be human-readable and easy to maintain, use the existing Makefile/compiler settings as a starting point, avoid changing shared adm/ settings, and compile only src_main/ instead of following the legacy gosh/compile.sh process that cleans/builds util/, map/src/, and src/.

The initial request deferred implementation pending plan review. The maintainer then explicitly approved Phase 0 implementation (full-tree copies, isolated build, and documentation) and asked to stop after a successful src_main/ compile. Phase 1's short, non-MPI Mekong simulation using map/mekong_15min/, inp/test-mek_1deg/, bifurcation enabled, and a period beginning 1980-01-01 is approved as the next task, but was explicitly deferred from this implementation.

The project instruction states that strict v4 numerical regression is generally unnecessary while v5 scientific calculation code is unchanged; practical operation checks are preferred. Any future scientific changes remain subject to the approval and validation boundaries in AGENTS.md.

## Formalization

The legacy preservation boundary is in AGENTS.md. The current project status proposal is in docs/dev_status.md. Build and test details are in docs/model_source_workflow_plan.md, src_main/README.md, and gosh_sample/README.md.

A repeated build check found that the copied Makefile could choose GNU Make 3.81's built-in Modula-2 .mod rule after the initial build because ext-libs was a phony normal prerequisite on three Fortran objects. The v5 copy now adds those order prerequisites only when EXT_LIBS is non-empty. The wrapper then completed twice. This fix is isolated to the v5 Makefile; extension-enabled configurations were not built.

Final parity review confirms that every other tracked source/workflow file is byte-identical: src_main/ differs only in its v5 Makefile and README, while gosh_sample/ differs only in its v5 compile wrapper and README. Build products are ignored and remain under src_main/. The v5 wrapper was also invoked from /private/tmp and successfully built src_main/ without relying on the caller working directory.

The first-run bifurcation contract was checked against source. cmf_ctrl_maps_mod.F90 reads the table selected by CPTHOUT when LPTHOUT is true; the source default for LPTHOUT is false, while the legacy standard example explicitly sets it true and the Mekong map contains bifprm.txt. The approved Phase 1 run will set it true explicitly. The wording that the model default is ON is not consistent with this source initializer; no global default change is made in Phase 0.
