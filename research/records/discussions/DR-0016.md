## Approved clarification

The standard basin-merging tool is general map preparation. The current MPI-specific chain is separate: `set_bif_basin_mpi` reads `basin.bin` and `bifprm.txt` and writes `bifbsn_mpi.bin`; `set_mpi_region` reads that MPI-specific map. Ordinary `bifbsn.bin` is not directly consumed in this verified chain. The maintainer's suggestion that the standard tool historically originated in MPI work is a hypothesis and is not recorded as fact.

The maintainer also confirmed that s02 is intended to follow s01 because it requires `rivhgt.bin` produced there. The two validation activities remain distinct: shared-tool migration regression and the complete s01-to-s02 chain. Neither is scientific validation.

## Failure evidence

The existing `map/tools/tests` suite had no focused s02 migration test. Its first run reported 31 of 32 base CTLs generated because `test_mekong_ctl_integration.py` copied `inpmat_test-15min_nc.bin` into its temporary fixture but omitted the paired, Git-tracked `diminfo_test-15min_nc.txt`. The file is an s03 output: `s03-generate_inpmat.sh` invokes `param_generate_inpmat`, which writes both the matrix and its dimension file. After adding that metadata to the test fixture, all 32 descriptors were generated; a second assertion issue expected zero fallback warnings although two registered variables intentionally have blank `missing_value` values. The test now checks generation/skip/failure counts and does not treat fallback warnings as missing descriptors. The high-resolution CTL count passes. The original incomplete fixture is preserved as historical evidence in `VR-0033` and superseded by the later passing suite record.

## Implementation and validation

The source header and step comments now distinguish channel bifurcations from all registered pathways, potential connectivity from dynamic inundation, and standard from MPI-specific outputs. The STEP-2 diagnostic was changed as explicitly approved; only nonnumerical diagnostic strings were corrected beyond that. The new test compiles both implementations under temporary build directories, runs on separate temporary map copies, checks the missing-depth guard, compares standard products byte-for-byte, and checks the optional diagnostic product. An optional integration case runs s01 to create `rivhgt.bin` and then runs s02. All generated outputs are discarded with the temporary directories.

Focused tests passed with compatible runoff climatology supplied from the local read-only CaMa-Flood package. Without that input, the focused s02 and guard tests pass and the full-chain test reports an explicit skip. The complete test discovery still has only the unrelated CTL failure described above. Research validation does not constitute scientific validation of the basin map.
