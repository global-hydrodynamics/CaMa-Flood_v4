## Question and context

The registry needs a functional role that can be filtered independently of `category_id`, which records processing order and product grouping. Existing `sub-id` values had been partially assigned manually, and the task required evidence-based completion without silently replacing those values.

## Evidence examined

- Runtime map loading/configuration: `src/cmf_ctrl_maps_mod.F90` and related model configuration.
- Input-matrix runtime reader: `src/mod/inpmat_mod.f90`, plus runtime examples in `gosh/`.
- Bifurcation, dam, and MPI configuration paths in `src/` and `gosh/`.
- Preparation and analysis consumers/producers under `map/src/` and `map/tools/`.
- Current `map/map_variables.csv` and `map/map_metadata_spec.md`.

## Alternatives discussed

No additional role values were approved. Unsupported entries were to remain blank rather than be assigned from filenames or presumed scientific use. Existing maintainer values were to be preserved even when code evidence suggests a conflict.

## Proposal (not yet a decision)

No proposal remains for the two role definitions; they were approved in the task instruction. The conflicting existing rows still require maintainer review before any reclassification.

## Maintainer decision and rationale

The approved labels are `A` for data used during model execution, including configurable alternative inputs, and `B` for preprocessing intermediates, diagnostics, and analysis data not directly used during model execution. These labels are independent of `category_id`. Only A/B are currently allowed. The separation supports numeric processing-order sorting and functional-role filtering without encoding both concepts in one field.

Ambiguous cases remain blank. Existing manual assignments must not be overwritten silently; source disagreements are to be recorded and raised for maintainer review.

## Implementation instruction, if any

Complete only classifications supported by repository evidence, document the field in `map/map_metadata_spec.md`, keep category values/order, check registry consumers (especially `generate_ctl.py`), and validate research records. Do not alter numerical behavior or unrelated registry fields.

## Outcome or unresolved questions

The CSV header is normalized to `sub_id` (underscore) while preserving its position as the second field. Forty-four blank rows received evidence-supported values. Existing A/B values were preserved. Runtime metadata for the configured runoff input-matrix files and paired dimension descriptions was corrected from the inspected reader/configuration paths. Nine rows remain blank. Five preserved A rows for regional-grid/no-edge preprocessing products are summarized in `KG-0004` and await maintainer review. Validation is recorded in `VR-0031`.
