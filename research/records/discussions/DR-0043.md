## Question and context

Phase C initially migrated three river-analysis utilities and deferred `get_vecmap`. The maintainer supplied a final specification for descriptive v5 names, migration of river-node coordinate extraction, and a portable collection of compiled tools and examples.

## Evidence examined

- Legacy programs under `map/src/src_param/`, including `get_vecmap.F90`.
- Shared v5 sources, build rules, shell examples, standard s06/s07 scripts, Mekong sample layout, registry, and regression tests.
- The task-approved architecture: shared compilation in `map/tools/code/`, optional portable examples and local executables in `script_analysis/`, standard product generation kept independent in `script_params/`.

## Alternatives discussed

- Keep migrated v5 tools under `analysis_get_*` names versus use concise, descriptive `analysis_*` names.
- Exclude vector-coordinate extraction from Phase C versus include it while preserving the legacy text format and geographic filter.
- Require a central shared executable path at runtime versus copy prebuilt executables into a self-contained map-local toolkit.
- Couple standard subbasin/upstream product generation to the optional analysis bundle versus retain separate shared-code workflows.

## Maintainer decision and rationale

The maintainer approved the final names `analysis_river_point_info`, `analysis_upbasin`, `analysis_subbasin`, and `analysis_river_node_latlon`. The unnecessary `get_` prefix is not used for these v5 programs. The old programs under `map/src/src_param/` remain unchanged.

The river-node tool is included as the fourth utility, preserving the legacy output rows, argument order (`WEST EAST SOUTH NORTH`), network semantics, and endpoint-in-box geographic selection. Its output describes directed links between CaMa-Flood representative points; it is not a high-resolution centerline or a GIS export.

`script_analysis/` is a portable, discoverable toolkit offering both direct executable access and readable shell examples. Compilation remains centralized in `map/tools/code/`; `a00-copy_codes.sh` explicitly copies already-built programs, with no implicit compilation. Standard `script_params/s06-subbasin.sh` and `s07-upbasin.sh` continue to use shared executables independently of copied analysis binaries. Their explicit standard-output paths and the safe analysis defaults keep exploratory CLI use from overwriting standard products.
