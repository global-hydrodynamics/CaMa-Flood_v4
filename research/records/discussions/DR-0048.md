## Context and authorization

The maintainer requested an ELSE_GPCC registry entry while keeping the source files outside Git and distribution packages, and a self-contained `inp/1deg_test/` workflow that regenerates the legacy two-year global 1-degree sample. Scripts, README, CTL and narrowly scoped ignore rules should be tracked; generated `Roff/` files remain excluded pending redistribution review.

## Evidence and implementation

The tracked source CTL describes a global 360×180, 1-degree little-endian float32 grid, N-to-S rows, `mm/day`, and `undef=-999`. A read-only filename/size audit found 11,688 expected-size daily files from 1979-01-01 through 2010-12-31, plus a zero-byte `Roff____20110101.one`; this differs from the CTL declaration of 7,671 records from 1981-01-01. The 2000–2001 sample period follows the legacy test sample coverage. The helper copies the daily files unchanged and writes a CTL describing the selected dates.

All 731 generated files matched their source files byte-for-byte and passed size, date-set and CTL checks. Only the source directory is read; the selected source file sizes and modification times were unchanged during execution. The source data and generated test binaries are ignored by Git, while workflow files are visible for tracking.

## Limits and open questions

The audit documents but does not resolve the source CTL/file inventory discrepancy (KG-0023). The unit is recorded as stated by the source CTL; byte identity does not independently validate physical meaning or scientific values. The Kim et al. citation does not establish redistribution permission (KG-0021). No CaMa-Flood simulation was run.
