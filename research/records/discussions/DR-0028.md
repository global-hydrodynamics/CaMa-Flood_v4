# DR-0028: Limit the `mod_` naming convention to shared map-tool modules

- Discussion ID: `DR-0028`
- Linked event IDs: `EV-0156`, `EV-0157`
- Source type: Maintainer instruction
- Source reference: Maintainer instruction in active Codex task; no transcript copied
- Source access: restricted
- Maintainer review: pending

## Question and context

The shared Fortran module source `map/tools/code/map_color_mod.F90` did not follow the maintainer's desired `mod_` filename prefix. The main CaMa-Flood model under `src/` has its own established naming convention.

## Evidence examined

References to the source filename and object were confined to the shared map-tools Makefile and two tests. The source declares internal module `map_color_mod`; callers use that name and procedure `color_map`.

## Alternatives discussed

No broader naming migration was requested. Renaming the internal Fortran module or applying the prefix to model sources would be an unrelated interface/convention change.

## Proposal (not yet a decision)

Rename only the shared module source file and update its build/test references.

## Maintainer decision and rationale

The `mod_` source filename prefix applies only to shared Fortran modules under `map/tools/code/`. It does not apply to `src/` or other directories. For this file, rename `map_color_mod.F90` to `mod_map_color.F90`, while retaining internal module name `map_color_mod` and procedure name `color_map`.

## Implementation instruction, if any

Update the shared Makefile and relevant documentation; do not alter the color algorithm or unrelated source files.

## Outcome or unresolved questions

The source file and its build/test references were renamed, and `AGENTS.md` now documents the directory-specific rule. The main model and all other directories were left unchanged.
