## Maintainer-approved decisions

- The standard v5 basin-preparation run writes `bifbsn.bin` and `bifcol.bin`; `bifcol.bin` remains unconditional because the maintainer routinely uses it to visualize the map.
- With `check_map`, `param_set_bif_basin` writes one two-record `check_bif_bsnmod.bin`: int32 record 1 is `bifmod`; int32 record 2 is `bpoint`. The existing classes and `-9999` missing-value convention remain unchanged.
- The same `check_map` option controls both programs. `param_set_bifparam` writes `check_bif_dphwth.bin` (depth, width), and `param_set_bif_basin` writes the consolidated basin diagnostics. Default execution must not create or overwrite either diagnostic; stale files are left in place.
- v5 no longer writes separate `bifmod.bin` and `bpoint.bin`. `biftag.bin` is excluded from the v5 product registry. Legacy code, legacy workflow files, and physical legacy data remain untouched.
- The interface/output organization changes, but the scientific calculations and classifications do not.

The supporting-data classification `sub_id=B` does not imply that a product is optional. This is why `bifcol.bin` remains an unconditional supporting product.

## Maintainer correction about CTL integration evidence

The earlier CTL integration failure was not caused by missing sample data. `diminfo_test-15min_nc.txt` is Git-tracked and is written with `inpmat_test-15min_nc.bin` by `s03-generate_inpmat.sh` calling `param_generate_inpmat`. The test copied the binary but omitted its paired text file in the temporary fixture. Adding the file produced every expected CTL; a follow-on assertion also needed to allow two existing fallback missing-value warnings. Both test-harness issues are corrected and the full suite now passes.

## Implementation and validation

The shared v5 basin utility accepts no argument or `check_map`, rejects other options, always writes `bifbsn.bin` and `bifcol.bin`, and conditionally writes the consolidated two-record diagnostic. The s02 wrapper passes the option to both utilities, checks/warns about the corresponding outputs, and does not inspect or overwrite diagnostics in default mode. The registry represents the consolidated file with two variable rows sharing a filename and record count. The CTL test verifies variable names and order.

Temporary-workspace regressions compare standard outputs and the two consolidated records with legacy `bifmod.bin` and `bpoint.bin`; the two diagnostic files are tested for default-preserve and explicit-write behavior. These are compatibility checks, not scientific validation. No legacy code, simulation algorithm, or map binary was changed.
