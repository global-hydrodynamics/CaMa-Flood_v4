- Observed: the FLOW area routine returns m2. The area-generation programs calculate the 10-by-10 source-pixel block area, multiply by 0.01 to obtain one source-pixel area, convert with 1e-6 to km2, sum only land pixels, and write -9999 when a cell contains no land. `generate_inpmat` substitutes positive `grdare` values and multiplies them by 1e6 to obtain m2; if `grdare` is absent, it keeps the geometry-derived area from the m2-returning area function. Mekong positive `grdare` values have median 3.1049 km2 and maximum 3.4063 km2; the global package has median 2.5747 km2 and maximum 3.4192 km2. `flddif` is computed as elevation relative to the unit-catchment reference river pixel. The maintainer defines `hand` as height above the nearest drainage river with upstream area >=0.5 km2; FLOW passes the supplied hand layer through. The maintainer confirms high-resolution `uparea` is in km2; the inspected FLOW merge path passes it through.
- Result: the `generate_inpmat` km2 assumption is supported by producer comments, generated area units, consumer conversion, and sample cell-area magnitudes. Registry and manuals now record all four definitions and units. Twelve v5 CTL tests and the research record validator passed.
- Scientific interpretation and limits: no FLOW or CaMa map-generation program ran. Sample statistics establish plausible units/order of magnitude but not scientific validity. HAND semantics and high-resolution uparea units are maintainer-confirmed, not independently derived from the inspected code.
