# VR-0118: Runoff forcing procedure refactor

- **Validation ID:** VR-0118
- **Event ID:** EV-0374
- **Task ID:** DT-0073
- **Source commit:** `6adceff0` (refactor validation ran in the worktree before commit)
- **Environment:** macOS workstation; GNU Fortran; NetCDF-Fortran and NetCDF-C.
- **Dataset:** Git-tracked Mekong map and test runoff samples. Temporary inputs, executables, and run directories were isolated under `/private/tmp`.

## Commands and observations

- `make -C src_main clean && make -C src_main all` — standard Binary build passed.
- `./gosh_sample/compile_netcdf.sh /private/tmp/MAIN_cmf_forcing_after` — NetCDF-enabled build passed.
- Temporary Mekong Binary forcing runs exercised `DAY`, `MON`, `YEAR`, and explicitly dated `SEQ` grouping. Grouped test files contained 40 daily records and covered day/month record selection; the SEQ test used the same 40 records. Each run completed before and after the refactor.
- Selected Binary `runoff`, `outflw`, `storge`, `sfcelv`, `flddph`, `fldfrc`, bifurcation `.pth`, and final Restart products were byte-identical for each grouping mode.
- A two-day NetCDF `YEAR` run from 2000-12-31 through 2001-01-02 crossed the annual-file boundary. All six selected NetCDF model outputs and the final NetCDF Restart were byte-identical before and after.
- An explicitly dated NetCDF `SEQ` Mekong run completed in both executables. Six selected NetCDF outputs and the final NetCDF Restart were byte-identical.
- NetCDF `SEQ` with CF-derived start time and omitted explicit date fields stopped with the existing `NFORCE` validation error in both the pre-refactor and refactored executables. This task did not change that behavior.
- No focused Forcing-specific test suite was present in the repository.

## Result and limits

Both build variants passed, and the tested grouped and explicitly dated forcing runs produced byte-identical selected outputs and Restarts. This is operational evidence for the tested Mekong configurations, not independent scientific validation. The existing CF-time `SEQ` startup error, optional MPI/coupled execution, and other compiler/platform combinations were not corrected or validated here.
