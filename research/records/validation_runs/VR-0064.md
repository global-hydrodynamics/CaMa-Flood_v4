# VR-0064: Initial allocation regression exposed dam-area unit mismatch

- Validation ID: `VR-0064`
- Event ID: `EV-0194`
- Task ID: `DT-0027`
- Source commit: `05258b288e1045e5d6c056ae30216a13f5e84793`; implementation worktree dirty
- Environment: macOS arm64, GNU Fortran 14.2.0; see [`environment_inventory.md`](../../baseline/environment_inventory.md)
- Dataset: tracked Mekong map files, selected GRDC/GRanD records, and explicitly synthetic boundary records

## Command and expected result

`python3 -B -m unittest map.tools.tests.test_allocation_regression -v`

The newly ported dam allocation products were expected to match the preserved v4 output snapshots in classification, row order, sentinels, output fields, and printed numeric precision.

## Observed result

The first regression failed for dam classification. Ordinary river cases fell into the `small` category in v5. Inspection found that the new port omitted the legacy conversion of positive `ctmare` values from m2 to km2 before comparing catchment area. Restoring that conversion made the output match the v4 snapshots. The v4 source was not modified.

- Result: **fail**, subsequently corrected
- Comparison: exact text fields and categories; floating values compared to output precision
- Scientific interpretation: this was a migration defect, not an approved scientific change. It demonstrates why output baselines are needed; it does not validate the scientific suitability of the legacy area criterion.
