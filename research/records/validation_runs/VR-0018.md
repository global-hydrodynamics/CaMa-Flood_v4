## Historical failing checks and causes

The previous `map/tests/validate_mekong_sample.py` expected a full model/package map, including `map_metadata.json`, channel parameter files such as `rivwth.bin`, `rivhgt.bin`, and `rivman.bin`, and bifurcation/runtime products absent from the current regionalization-stage GitHub sample. Its failures were incorrect test assumptions about sample completeness, not evidence that regionalization had failed. It was replaced with fixture checks for the products actually tracked and needed by map-tool tests.

The earlier dry run and maintainer-generated CTL output exposed a real v5 metadata/parser defect: `downxy.bin`, `1min.flwdir.bin`, and `1min.visual.bin` were skipped because numeric sentinels were mined from prose, and `v5` text in the `catmz100`/`catmzz` descriptions was incorrectly read as sentinel `5`. The generator returned success despite these skips. The schema now supplies numeric values directly, and the wrapper test checks generated/skipped/failed/fallback counts rather than relying only on exit status.

## Interpretation and limits

The new numeric `missing_value` column contains values only where an existing code, sample, or maintainer confirmation established them. Blank cells remain unresolved or not applicable; the v5 CTL generator uses type-specific defaults only for visualization and emits warnings without writing those assumptions back to the registry. `special_values` keeps known endpoint and categorical meanings separate from missing data. GrADS 2.2.1 documentation specifies byte input as unsigned, so the CTL's `undef 247` masks the same stored byte as signed `-9`; other negative int8 values display as unsigned. The local GrADS batch attempts did not yield an interpretable data query, so CTL-file reading by a live GrADS session is not claimed as validated here.

No Mekong sample-preparation/regionalization script, model simulation, river-network scientific validation, or v4/v5 numerical comparison was run. Sample preparation, software tests, and scientific validation are separate activities. The existing user CTL modifications and deletions remain untouched.
