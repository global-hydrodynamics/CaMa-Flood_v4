# VR-0091: Individual Binary/NetCDF map input comparisons

- **Task:** DT-0047
- **Event:** EV-0286
- **Source revision:** `fd20a0950325e40d9a01301a6b83956ef3cc5356` plus the task worktree changes; no commit was created.
- **Environment:** macOS arm64 workstation, GNU Fortran with OpenMP, Homebrew NetCDF-C/Fortran, Python 3; converter uses Python standard library and NetCDF C API.
- **Result:** Pass for the requested build, conversion, 40-day operational comparisons, and negative input checks. This is not independent scientific validation.

## Builds and conversion

The final `src_main/cmf_ctrl_maps_mod.F90` compiled successfully twice: once through the ordinary Binary-only `make clean && make all`, and once with `UseCDF_CMF` plus the installed NetCDF C/Fortran flags. The final converter generated temporary NetCDF counterparts for `nextxy_noedge`, `ctmare`, `elevtn`, `nxtdst`, `rivlen`, `fldhgt`, `rivwth_merit`, `rivhgt`, and `rivman`. The converter read each variable/layer back through NetCDF and compared decoded bytes to the Binary record. Both `nextxy` records and all ten `fldhgt` layers were included.

## Simulation cases

All runs used the same 40-day Mekong sample configuration: 2000-01-01 00:00 through 2000-02-10 00:00 (exclusive), daily Binary runoff, the existing input matrix, non-MPI, four OpenMP threads, bifurcation and adaptive timestep enabled.

| Case | Map inputs | Exit |
| --- | --- | --- |
| T1 | All nine core map inputs Binary, NetCDF-enabled executable | 0 |
| T2 | `rivhgt` NetCDF; all other core map inputs Binary | 0 |
| T3 | `nextxy_noedge` NetCDF; all other core map inputs Binary | 0 |
| T4 | `nextxy_noedge`, `ctmare`, `elevtn`, `nxtdst`, `rivlen`, `fldhgt`, `rivwth_merit`, `rivhgt`, `rivman` NetCDF | 0 |
| Binary-only | All core map inputs Binary, regular Binary-only executable | 0 |

`outflw2000.bin`, `storge2000.bin`, `sfcelv2000.bin`, `flddph2000.bin`, and `fldfrc2000.bin` were 1,536,000 bytes each. T2, T3, and T4 matched T1 byte-for-byte for all five files (maximum absolute difference 0). The Binary-only run matched the earlier Binary baseline byte-for-byte for the same five outputs.

Negative tests failed with nonzero status and identifying diagnostics for an unsupported extension, a missing NetCDF variable, a dimension mismatch, `.nc` input on a Binary-only executable, and legacy `LMAPCDF=.TRUE.` on a Binary-only executable.

## Limits and interpretation

The implementation and model checks passed. The complete research-record validator was also run, but it stopped at a pre-existing cross-reference inconsistency: `events.csv` EV-0033 references VR-0009, whose Markdown detail exists but whose row is missing from `validation_runs.csv`. This dangling reference is documented in VR-0090. A focused schema scan also found pre-existing extra-column rows for KG-0018 and KG-0022 in `knowledge_gaps.csv`; the newly added rows have the expected column counts. These archival issues were not repaired here because they predate the task and are unrelated to Map I/O. The overall record is therefore a partial pass for the combined checks.

These checks demonstrate value-preserving conversion and operational I/O equivalence for the tested Mekong core inputs. They do not establish scientific correctness, all-platform reproducibility, or behavior for optional groundwater delay, mean sea level, MPI region maps, slope/mask inputs, or legacy consolidated NetCDF containers. A suitable consolidated-container fixture was unavailable, so preservation of that mode was source-inspected and build-guarded but not runtime-tested. The NetCDF-enabled build was exercised on macOS/Homebrew only; MPI-specific compilation/runtime and Linux have not been tested.
