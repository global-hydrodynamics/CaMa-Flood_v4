## Comparison method and result

The historical MPI Fortran programs and the v5 shared programs were built and run in temporary map copies in both `normal` and `MaxMPI` modes. For each mode, basin-group IDs and the 4-, 8-, and 16-region maps were compared byte-for-byte. All compared arrays matched exactly (zero differing cells). The standard `bifprm.txt` was unchanged. The source-row deterministic fallback and basin sorting were also exercised with parsed, layer-independent reference cases; identical-key/elevation records and repeated runs were tested.

Region river-cell load summaries (minimum–maximum across regions; maximum/minimum ratio) were:

| Mode | 4 regions | 8 regions | 16 regions |
| --- | ---: | ---: | ---: |
| normal | 1641–1642 (1.0006) | 673–1414 (2.1010) | 231–1414 (6.1212) |
| MaxMPI | 1641–1642 (1.0006) | 673–1414 (2.1010) | 233–1414 (6.0687) |

The load values count assigned river cells. Their imbalance is a property of the preserved greedy region algorithm and should not be interpreted as a measure of runtime balance or simulation accuracy.

The old shell command used fixed field keys (15, 16, 6); the v5 parser selects fields by meaning, so it works with other supported layer counts. Legacy output agreement was observed for the Mekong configuration, including normal and `MaxMPI`; no claim is made for every compiler, map, locale, or tie pattern.
