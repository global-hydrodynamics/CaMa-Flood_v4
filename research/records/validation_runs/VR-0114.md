## Commands and observations

`make -C map/tools/code param analysis` compiled the migrated Fortran consumers. The focused suite ran as:

```sh
PYTHONPATH=/private/tmp/cmf-netcdf4 python3 -B -m unittest \
  map.tools.tests.test_bifurcation_migration \
  map.tools.tests.test_mpi_map_tools \
  map.tools.tests.test_script_workflow_messages -v
```

All 25 tests passed. The sample tests verified consecutive pth_id values, unique `(ix,iy,jx,jy)` tuples, source coordinate preservation, end outlet coordinates from `lonlat.bin`, NetCDF dimensions/dtypes/metadata/compression, and cross-format values for every field. Standard basin output matched the legacy binaries exactly. MPI region preparation and diagnostic cases passed, including a reordered CSV header, repeatability, and downstream-vector edge behavior. A duplicate endpoint tuple was rejected while a pre-existing target NetCDF remained unchanged.

`python3 map/tests/validate_map_variables.py` passed with 106 entries. Shell syntax checks, Python AST parsing, local Markdown-link checks, and `git diff --check` passed. The research record validator was also run and reported the already existing `EV-0034` reference to missing `VR-0009`; no earlier record was changed.

## Result and limits

For the tested Mekong data, the CSV and NetCDF represent the same finalized path table. Serial and MPI preprocessing compatibility checks passed. This is map-workflow and data-contract validation, not independent scientific validation. The current simulation reader continues to require `bifprm.txt`. The `bifori.txt` header coordinate-label discrepancy remains unresolved; this migration preserves the legacy reader interpretation.
