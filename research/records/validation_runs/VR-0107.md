Compiled a temporary Fortran harness against the Binary build. It called the public forcing reader for synthetic DAY, MON, YEAR, and SEQ inputs; checked setting-presence detection; tested Gregorian leap and no-leap indexing; and checked `DATE2MIN`/`MIN2DATE` round trips at day, month, leap-day, and year boundaries. Expected filenames, record numbers, and Float32 values were known in advance.

## Observed result

Both builds passed. The Binary sample completed and its model log showed `CROFFREQ: DAY` plus daily file opens starting with `Roff____20000101.one`. The continuous NetCDF sample completed and opened both annual files, with the expected 2001 file switch. Synthetic Binary reads returned the expected records for all four grouping modes. The date tests showed that accepted `24:00` and minute `60` values normalize through `MIN2DATE` before filename selection. The setting scanner ignored a variable-like token in a quoted string/comment and ignored a later `&NFORCE` group after the first group ended.

`bash -n` passed for the modified sample scripts, `git diff --check` passed, and the changed README links resolved. `python3 research/validate_records.py` remains blocked by the pre-existing `EV-0034` reference to missing `VR-0009`; that reference was present before this task and was not changed.
