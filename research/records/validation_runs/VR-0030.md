# VR-0030: Mekong CTL integration test fixture omitted paired metadata

- Validation ID: `VR-0030`
- Event ID: `EV-0096`
- Task ID: `DT-0004`
- Source commit: `f2210904afbe80e182b589d850238b9422e26ff8` (HEAD before this task; tested after branch-local B2.3 edits)
- Worktree state: Integration test copied the Git-tracked sample to a temporary tree; no committed CTLs or map data were modified.
- Environment: macOS arm64; Python runtime recorded by the invoking environment.
- Dataset: Current Git-tracked `map/mekong_15min/` sample copied by the test.

## Check and result

- `python3 -B -m unittest map.tools.tests.test_mekong_ctl_integration -q` — **failed** its expectation that all 30 base-map binaries receive CTLs. The actual summary was 29 generated and 1 skipped, plus 12 high-resolution CTLs generated.
- The skipped file was `inpmat_test-15min_nc.bin`, because the test copy lacked `diminfo_test-15min_nc.txt`. That metadata file is present and Git-tracked in the sample; the integration fixture copied the matrix binary but omitted its paired text metadata.
- The independent CTL unit suite passed all 17 tests. The missing pair is unrelated to the bifurcation metadata or programs in B2.3. No sample or test changes were made to conceal the gap.

## Interpretation and limits

This was a test-fixture completeness issue for CTL generation, not a missing sample product or a failure of the B2.3 bifurcation migration. The s03 wrapper invokes `param_generate_inpmat`, which writes both the matrix and its dimension descriptor. The fixture omission was later corrected; see `DR-0016` and the follow-up passing suite record. The original failed run remains as historical validation evidence.
