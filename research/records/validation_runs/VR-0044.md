## Result

An MPI-enabled build was attempted with `DMPI=-DUseMPI_CMF`. The initial parallel (`-j2`) build failed because the existing Makefile allowed `yos_cmf_input.F90` to compile before `parkind1.mod` was available. A serial retry compiled the MPI model objects but failed at link with unresolved external `_conv_endi_`, referenced by `cmf_ctrl_maps_mod.F90`'s `CALC_REGION`. That contained routine calls `CONV_ENDI` but has no visible `USE CMF_UTILS_MOD` import; the existing module implementation is a module procedure. This is a pre-existing model-build issue outside the approved map-tool source changes.

No MPI simulation was run. Although `mpif90` and `mpirun` are installed, an executable could not be linked, so the requested runtime pairing check of standard `bifprm.txt`, selected `mpireg-N.bin`, and MPI process count remains pending. `gosh/test5_mpi.sh` was inspected and contains this pairing, but was not edited or executed.

## Follow-up

This exploratory build result does not block the current map-tools milestone. The maintainer has clarified that `src/` and `gosh/` modifications and testing are outside this task. If a later task requests model runtime integration, first scope the existing build issues separately. Do not attribute the connectivity diagnostic's source-level match to a completed MPI simulation.
