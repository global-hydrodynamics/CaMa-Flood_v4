# Japan hourly runoff sample at 6-arcmin resolution

This sample is derived from the existing 1-arcmin Japan hourly binary sample in `inp/test_jpn_1hr/`. The maintainer confirms that the underlying 1-arcmin runoff came from simulations using the Today's Japan system, was provided by Yoshimura Laboratory, and has redistribution permission. The 6-arcmin files are spatially aggregated from that 1-arcmin sample; they are not observations and are not an independent 6-arcmin Today's Japan simulation.

The 1-arcmin sample is retained internally as the source/reference dataset. This smaller, reproducible product is intended to replace it for routine repository distribution. The original data are accessed through the local `inp/test_jpn_1hr` symbolic link; that link and its large source files are excluded from Git and are never modified by the workflow.

## Grid and time coverage

- Domain edges: 123–148°E, 24–46°N.
- Source: 1/60 degree (1 arcmin), 1,500 × 1,320 cells, stored north-to-south (`yrev`).
- Output: 0.1 degree (6 arcmin), 250 × 220 cells, stored north-to-south.
- Time: 2007-09-03 through 2007-09-09 inclusive, 168 hourly records.
- File layout: seven `runoff_YYYYMMDD.bin` files, each holding 24 consecutive little-endian float32 records in chronological order.
- Missing value: `-9999`; if any of the 36 source pixels in a target block is missing, the target cell is written as `-9999`. This avoids treating missing source values as zero. The inspected source sample has no missing values.

## Unit caveat

The original source `runoff.ctl` says `mm/day`; the maintainer identifies that label as erroneous and assesses the values as `mm/hour`, consistent with [`gosh/test3-jpn_fcast.sh`](../../gosh/test3-jpn_fcast.sh) (`IFRQ_INP=1`, `DROFUNIT=3600000`). The aggregation preserves the numeric values and writes the corrected `mm/hour` label to the new CTL; it performs no unit conversion. This is the maintainer's interpretation and has not been independently verified against additional source metadata.

## Reproduce the aggregation

Ensure the source link is present and points to the v4.30 package's `inp/test_jpn_1hr/` directory. NumPy is the only non-standard Python dependency. Run the shell entry point by path from any working directory:

```sh
/path/to/CaMa-Flood_v4/inp/test-jpn_6min_1hr/s01-aggregate_runoff.sh
```

The source directory is configurable at the top of `s01-aggregate_runoff.sh`; its default `../test_jpn_1hr` is resolved relative to the script, not the caller's current directory. The script writes only into this real `inp/test-jpn_6min_1hr/` directory. The adjacent `aggregate_runoff.py` checks the source CTL, dates, grid, byte order, record count, and file sizes before reading. It applies an area-weighted average over each 6 × 6 source-cell block, using latitude-dependent spherical cell areas (`R² Δλ [sin(φnorth) − sin(φsouth)]`). Longitude widths are equal within each block; the complete cell-area weights are used in the mean. No temporal averaging, interpolation, or unit scaling is performed.

The run also checks output names and sizes, the output CTL grid/time metadata, source-file size and modification times, source value anomalies, integrated runoff conservation for every hour, and selected block means calculated independently with scalar loops. Conservation is expected to numerical precision when source blocks are complete; the helper compares like-for-like areas if missing blocks occur.

Expected binary size is 5,280,000 bytes per day and 36,960,000 bytes total, plus `runoff.ctl`. The `.bin` files are explicitly unignored by this directory's `.gitignore` so the validated compact sample can be tracked. The original `test_jpn_1hr` link and source data remain excluded.

## CaMa-Flood settings

Use a distinct runoff tag for an input matrix generated for the selected map:

```sh
ROFFTAG="test-jpn-6min-1hr"
GRSIZEIN=0.1
WESTIN=123
EASTIN=148
NORTHIN=46
SOUTHIN=24
OLAT="NtoS"
```

The matching existing hourly binary forcing setup is:

```text
LINPCDF = .FALSE.
LINPDAY = .TRUE.
LINTERP = .TRUE.
IFRQ_INP = 1
DROFUNIT = 3600000  # mm/hour to m/s; source unit per maintainer assessment
CROFDIR = inp/test-jpn_6min_1hr
CROFPRE = runoff_
CROFSUF = .bin
CINPMAT = map/<selected-map>/inpmat_test-jpn-6min-1hr.bin
```

The input matrix is map-specific and is not generated by this runoff aggregation workflow. Do not overwrite the existing 1-arcmin matrix. Confirm the runoff unit interpretation before treating the configured divisor as scientifically verified.

## Verification status

The source CTL and seven source files were inspected read-only. All seven dates contain 24 records of 1,500 × 1,320 little-endian float32 values; the sample contains only finite, nonnegative values and no `-9999` cells. The generated files are 5,280,000 bytes each (36,960,000 bytes total; 36,184 KiB allocated on the workstation). All 168 records passed the area-integral comparison: maximum relative difference was 1.285 × 10⁻⁸ and mean relative difference was 2.160 × 10⁻⁹ after float32 output rounding. Nine independently calculated 6 × 6 block means passed checks at the first day’s 00:00, 12:00, and 23:00 records. Output names, record counts, byte sizes, and CTL grid/time metadata passed validation; source sizes and modification times were unchanged during the run. The maintainer identifies the source CTL’s `mm/day` label as incorrect and assesses the source values as `mm/hour`; the generated CTL now uses `mm/hour`. This unit interpretation is not independently verified against source-product documentation. The checks establish data-layout consistency, spatial conservation, and reproducibility, not the scientific validity of the underlying runoff simulations.
